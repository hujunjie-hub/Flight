# 飞控核心模块与控制系统设计（V1.9.1）

> **规范性：** 本文件是M5/M6/M7算法、控制数学和执行器边界的唯一详细来源；M3公共接口见02号ICD，QUAD_X4首版KF-GINS内部实现唯一见05号文档。


> **项目落位：** INS、FMS、控制和 Plant 在 `middleware/model/`，各自的公共 C 接口位于模块根目录。OSQP 随 QUAD_X4 外环，KF-GINS 随 INS。控制预测模型归外环，Host 的 `plant_sim_*` 入口归 `plant/plant_interface.c`。当前物理模型由外部 FMT-SIM 提供，Host 的合成传感器夹具位于 `tests/support/sensor_sim/`。Plant 接口只参与 Host 构建。M7 复用平台的 Timer/PWM/DMA 驱动。目录与构建见 03 §0。

## 2. M2 SENSOR MANAGEMENT

### 1. 职责

M2 将原始设备数据转为带统一单位、frame、sample time、校准版本和样本质量的标准测量；负责解码、校准应用、滤波/预处理、采样时间质量、设备/样本级诊断。M2 不做组合导航，不维护源级隔离状态，不决定操作模式。

### 2. 处理链

原生 RT-Thread Device/Bus Driver -> DMA/FIFO/Buffer -> acquisition worker -> decoder -> calibration apply -> bounded filter -> timestamp/quality -> typed measurement -> M3。

采样时刻必须来自设备时间戳、硬件捕获或 FIFO 时间重建；DMA 完成/RTOS 唤醒时间只能用于延迟测量。

### 3. 质量输出

每个样本至少区分 VALID、DEGRADED、INVALID、UNSYNCHRONIZED、STALE。设备健康和样本质量分开：设备在线不代表样本有效；某个样本无效不代表设备永久损坏。

诊断包含 reason code、sample sequence、sample age、calibration version、saturation/stuck/range/timing flags、连续计数和最近有效样本时间。

### 4. 传感器异常边界

- CRC/格式/时间倒退/冻结/饱和/超量程：M2 标记样本质量和证据。
- 磁场随电机电流变化、气压受 propwash、光流低纹理、测距超适用域：标记条件退化，不轻易宣告设备故障。
- 突发高加速度可能是真实冲击或外部扰动；M2 报告原始样本质量/饱和事实，不判断风/鸟/碰撞原因。
- M2 不因 M3 innovation 高而自行隔离传感器。

### 5. 资源与接口

固定容量、静态分配、显式 buffer ownership；高频 IMU 使用专用有界环形通道，异步观测按 sample time 排序。DMA buffer 不得放入不可访问的 TCM 区域；Cache/MPU 按平台规范处理。

### 6. 参数

传感器型号、ODR、FIFO 和总线配置属于 Product Manifest/驱动；样本年龄、饱和、冻结和去毛刺规则属于 M2/设备适配的质量策略，不作为日常调参项；若新硬件确需改变，提交 CR 而不是新增一批通用 YAML 旋钮。需要工程辨识的传感器安装旋转、杆臂和剩余时间偏差统一来自 `config/sensor_alignment.yaml`；原始校准报告归档在 `doc/calibration/`。

### GNSS主要器件与运行中观测丢失行为

- 当前产品固定安装UM982，UART4 GNSS实例、RX DMA、GNSS质量/健康监控和PPS捕获路径始终创建；不允许默认关闭或以未安装掩盖设备故障。
- GNSS已安装但无Fix时，设备可为PRESENT，GNSS测量样本为NO_FIX/INVALID；不影响IMU采集和本地时间。
- M2对每个样本保留sample time、capture time、DMA complete time、publish time、clock/time/mapping epoch及time uncertainty。
- IMU DRDY时间来自PA3/TIM2_CH4硬件捕获；无GNSS时该路径不变。
- GNSS导航质量、GNSS时间历元质量和PPS边沿质量分别发布；M2不得将其中一个状态直接复制到另一个状态。
- 无GNSS时仍输出有效的本地monotonic时间；没有可信UTC时UTC字段无效，不得填充系统启动秒数或默认日期。

## 3. M3 NAVIGATION ESTIMATOR

### 1. 唯一职责

M3 从 M2 标准测量估计车辆运动状态和不确定度，完成 INS 传播、观测融合、观测级一致性检查、单次观测拒绝、状态重置管理和 NavigationCapability 发布。M3 只回答“车辆在哪里、怎么运动、估计可信到什么程度”。

M3 不负责任务/模式/权限、返航/降落/停车/靠泊、传感器源级永久隔离、FMS 安全响应、路径规划和控制器切换。

### 2. 可替换边界

`EstimatorPort`固定输入测量/时间/源策略，输出NavigationSnapshot/NavigationCapability/StateResetEvent/EstimatorHealth。插件内部观测门控与诊断不进入公共ICD。KF-GINS_QUAD为QUAD_X4首版设计选定实现（未代表实现/目标验收批准）；其他产品可在Profile中选择符合EstimatorPort的UKF或其他完整估计器。算法内部状态维数、协方差、误差状态和观测模型不泄漏到公共接口。

### 3. 首版四旋翼实现

QUAD_X4首版采用KF-GINS 21维核心误差状态+1维气压高度偏置（22维），保留双子样INS机械编排；GNSS位置/速度、Baro高度和质量门控Mag航向按05号文档扩展。内部double精度为初始数值基线，固定维数矩阵、无heap；噪声密度和初始协方差来自`config/estimator_tuning.yaml`。延迟窗口、状态维数、观测模型和NIS统计策略属于算法/实时结构，不作为普通调参项。

### 4. 观测异常处理

- M2 invalid/unsynchronized/stale 样本不得直接融合。
- 每次观测独立执行时间、frame、origin、covariance、innovation/NIS 和适用域检查。
- 单次异常只拒绝该观测或延迟处理，并记录插件内部EstimatorDiagnostic；该私有记录不作为公共ICD消息，也不得直接把SensorHealth改成QUARANTINED。
- 持续残差异常要检查时间同步、杆臂、坐标、模型适用域、真实机动和共因故障。
- 当多个独立源共同支持突发运动时，允许估计真实运动；不得为了让残差变小而错误拒绝所有传感器。
- 对疑似 GNSS spoof/jamming、VIO reset、轮速打滑、水速/流速耦合等，按观测模型与产品能力输出明确质量/能力退化。

### 5. 导航能力

NavigationCapability 应表达位置/速度/高度/航向/姿态的有效性和不确定度，以及 active/rejected source mask。导航能力按任务所需维度分别判断；磁力计失效不等于位置解失效，GNSS 失效不等于惯导立即失效。

### 6. 状态重置

外部 VIO/SLAM reset、GNSS origin change、坐标原点更新、估计器重初始化必须发布 StateResetEvent 并增加 state_epoch/origin_id。M5/M6 必须识别 epoch 变化，禁止把 reset 跳变当作真实运动指令。

### 7. 输出诊断

KF-GINS_QUAD内部EstimatorDiagnostic记录measurement_id、source_id、sample time、gate result、normalized residual/NIS、适用域标志和原因，供M3内部调试/日志使用；跨模块只发布02号ICD定义的NavigationCapability、EstimatorHealth和源恢复专用SensorConsistencyEvidence，不发布私有诊断结构。Sensor Integrity Manager依据M2设备/样本级事实、EstimatorHealth和按源聚合的一致性证据判断源级状态，不读取KF-GINS私有残差结构；单次NIS拒绝不能触发源级隔离。

### 8. 参数

只有噪声模型和初始不确定度进入 estimator tuning。NIS/innovation gate 按统计自由度和固定置信策略计算；延迟窗口、更新率和初始化流程属于算法/硬件时序设计，变更走代码评审与验证，不暴露为普通调参旋钮。

### GNSS观测中断时估计器运行边界

M3必须在UM982始终接入而有效GNSS观测暂不可用时继续处理有效IMU和其本地单调sample time；不得通过裁剪GNSS来实现容错。GNSS中断不会停止预测或改变IMU dt来源，但导航能力必须随协方差和可观性降级。

- 启动未获Fix、运行中失锁或链路中断：保留GNSS队列/源健康对象，发布未就绪或丢失状态；队列为空不等于设备未安装。
- GNSS无Fix/丢失：拒绝无效GNSS观测，保留最后状态但按过程噪声持续增长协方差；NavigationCapability必须反映漂移和可观性下降。
- IMU+Baro/Mag通常只能提供姿态/航向/相对高度辅助，不提供水平绝对位置。
- IMU+Optical Flow+Range可在纹理、光照、倾角、距离和运动范围内提供局部速度/相对位置；不能宣称全球位置或无界无漂移。
- IMU+VIO/SLAM可提供局部位置/速度；必须处理tracking quality、reset counter、origin和外部clock mapping。
- 外部时间映射不可信的VIO/Companion数据不得按接收时间伪装曝光/测量时间；按uncertainty门控或拒绝高动态融合。
- M3只发布状态、协方差、来源和NavigationCapability；不得因无GNSS决定LOCAL_RETURN、LAND或其他操作。

## 4. 车辆模型、控制模型与 Plant Simulation 接口规范

### 1. 目的

把“被控对象”相关概念拆清楚，使四旋翼、UGV、USV、MATLAB/Simulink 模型可替换，同时不把仿真模型塞进 H723 实时控制链。

### 2. 五类对象

| 类型 | 使用方 | 作用 | 是否进 H723 |
|---|---|---|---|
| Physical Plant | 真实系统 | 实际车体/执行器/环境 | 真实硬件，不是软件模块 |
| Estimator Model | M3 | IMU 传播、观测模型、车辆运动约束 | 是，随 Estimator 实现静态链接 |
| Control Prediction Model | M6 | MPC/LQR 预测、线性化、控制约束 | 是，必须固定维数和 WCET |
| Plant Simulation Model | SIL/HIL | 高保真刚体/车辆/环境响应 | 否，仅 Host/仿真目标 |
| Actuation Data | M6/M7 | M6 控制效能/分配；M7 物理需求到设备命令标定 | 按职责分别进入 |

不要创建一个所有模块都能访问的万能 `PlantModel`。

### 3. 模型 Port

#### 3.1 ControlModelPort（M6）

输入/输出维数由 Product Contract 编译期固定。实际API固定为02中的 `control_model_get_descriptor/get_view/validate/predict/get_linear_model/get_constraints/check_domain`，不另建同义函数。LTI 模型返回常量离散 A/B/c；LTV/LPV 只在有界工作点内线性化；非线性预测必须有固定执行上限。模型越界返回 OUT_OF_DOMAIN，不得静默外推。

#### 3.2 PlantSimulationPort（Host/SIL/HIL）

固定为02中的 `plant_sim_init/reset/step`，truth由step输出，不存在隐含get_truth/get_info。输入为物理 `ActuatorDemand` 或经 HIL Adapter 转换的实际应用需求，加环境输入和固定步长；输出 PlantTruth 和 SensorTruth。PlantTruth 只用于评估/传感器仿真，不进入 M3/M6 闭环。Plant Simulation Model 可以比目标控制模型复杂得多。

#### 3.3 SensorSimulationPort（Host/SIL/HIL）

从 PlantTruth 和传感器配置生成带 sample time、噪声、延迟、偏置、量化和故障注入的模拟测量，再通过 M2 标准测量接口进入 M3。禁止直接把 PlantTruth 转成 VehicleState。

### 4. 不单独暴露的模型

Estimator Motion/Measurement Model 默认是所选 Estimator 插件的内部组成；M3 负责其生命周期。除非多个估计器确实共享且需要独立替换，否则不建立额外公共 EstimatorModelPort。Actuator Dynamics 默认属于 Plant Simulation Model；M6 的执行器效能数据和 M7 标定映射分别由各自 Owner 管理。

### 5. Actuation Data 分离

- `ActuationEffectivenessData`：执行器位置/旋向/效能矩阵/可用范围，M6 allocator 只读使用。
- `ActuatorCalibrationMap`：推力/舵角/推进需求到设备命令的映射，M7 使用。
- `ActuatorDynamics`：电机/舵机/推进器延迟、惯性和动态，Plant Simulation Model 使用。

不得把三者混为一个 ActuatorModelOps。

### 6. 车辆模型示例

- QUAD_X4：Plant 为 6-DOF 刚体+电机/桨动态+气动/环境；Estimator 为 IMU/KF-GINS_QUAD+GNSS位置/速度、Baro高度和质量门控Mag航向；Control Model 首版为 6 状态/3 输入双积分器 LTI；M6 内部唯一为 MPC→推力映射→SO(3)→Rate PID→X4 allocator；首版不启用ADRC/LESO。
- UGV：Plant 为运动学/动态自行车模型，必要时加轮胎/侧滑/附着；Estimator 融合 IMU/GNSS/轮速/转向；Control Model 可为自行车模型；Controller 使用速度/转向控制，不使用 SO(3) 电机混控。
- USV：Plant 为 surge/sway/yaw 3-DOF 水动力+推进器/舵+风流；Estimator 融合 IMU/GNSS/航向/水速；Controller 使用 3-DOF MPC/LOS/PID 和推进器分配。

### 7. 模型 Manifest 与有效域

每个模型必须记录 ID/version/hash、产品 Profile、状态/输入 layout、单位/坐标、参数来源、固定步长、适用速度/载荷/电压/温度/环境范围、线性化有效域、数值精度、代码生成配置和 golden vectors。超出适用域返回明确错误并触发 M6/M3 降级策略。

### 8. H723 约束

Control Model 固定维数、固定矩阵/工作区、静态内存；LTV/LPV 的线性化 WCET 必须测量。Plant Simulation Model 和复杂传感器仿真不编入 H723 实时固件。H723 只链接所选产品的 estimator/control/actuator 实现。

### 参数来源与异常证据（V1.9.1现行规范）

QUAD_X4 的质量、重心、惯量、旋翼几何、推力曲线和电机时间常数统一来自 `config/vehicle_model.yaml`；Host Plant、Control Model 和 M7 推力映射使用同一权威模型数据/派生结果，不得分别维护副本。环境扰动场景属于仿真场景数据，不是车辆固有调参。Control Model 适用域外的预测残差应报告 MODEL_MISMATCH/OUT_OF_DOMAIN，不得直接认定传感器异常。外部扰动由仿真环境显式注入并验证 M3/M6/M7 证据链。

## 5. MATLAB / Simulink 模型开发与集成规范

### 1. 定位

MATLAB/Simulink 是建模、辨识、算法设计、代码生成和 SIL/HIL 工具，不是 H723 运行时依赖。模型必须通过项目 Adapter 实现已冻结的 Port；公共 ICD 不引用 Simulink Bus Object、模型内部信号名或生成代码私有结构。

### 2. 模型类型分开管理

- `Plant.slx`：高保真被控对象和环境，Host/SIL/HIL。
- `Actuator.slx`：电机/ESC/舵机/推进器动态，通常作为 Plant 子系统。
- `Sensor.slx`：采样、噪声、偏置、延迟、量化和故障注入。
- `ControlPredictionModel`：供 M6 MPC 使用的降阶/线性化模型，可由 Simulink 线性化导出固定矩阵或 C Adapter。
- `Controller.slx`：可选控制器参考实现/代码生成源。
- `Estimator.slx`：可选导航算法原型/参考实现，不改变 EstimatorPort。

Plant Model 和 Control Prediction Model 不可互相替代。Plant Truth 只用于评估和 Sensor Model 输入。

### 3. 接口

Plant 输入为 M7/M6 产生的物理 ActuatorDemand（HIL Adapter 负责安全转换）；输出 PlantTruth 和 SensorTruth。Sensor Model 生成 ICD 强类型模拟测量，经 M2/M3 链路形成 NavigationSnapshot。Controller/ControlModel 必须符合对应 Product Contract 和 Port。

### 4. SIL/PIL/HIL

- SIL：Host 运行控制/导航实现和 Plant/Sensor Model；闭环只使用模拟测量→M2→M3。
- PIL：目标处理器运行所选算法，Host 提供测试向量并采集输出，比较数值和执行时间。
- HIL：H723 运行真实固件，实时仿真器运行 Plant/Sensor；ActuatorDemand 经隔离接口进入仿真，模拟传感器返回 M2。PlantTruth 只用于误差评估。

### 5. 代码生成约束

固定步长、固定维数、固定采样时间；禁止 variable-size signal、动态内存、无界循环、不可控阻塞和 MATLAB Runtime。生成代码通过 C Adapter 封装，不直接暴露全局变量。代码必须经过静态分析、WCET、RAM/Flash、栈和数值等价性测试。

### 6. 模型一致性

每个 `.slx`、参数集、求解器配置、生成代码、工具版本、采样周期和测试数据记录 hash。手写 C 与 Simulink 使用同一 golden vectors；更新 Plant/ControlModel/Controller 必须触发对应 SIL 回归。

### 7. 禁止

## 6. QUAD_X4 M5/M6/M7 唯一算法与控制实现规范

本章是QUAD_X4的详细算法定义；前文只作模块边界摘要，不能形成第二套数值或“后章覆盖前章”规则。公共类型/调用只由02定义；物理参数证据与算法定义分开，未验证实物值不以示例填充。

### 1. 坐标和状态契约

- 导航坐标：NED，x北、y东、z下；机体坐标：FRD，x前、y右、z下；右手系。
- `R_nb`将Body-FRD向量变换到Nav-NED；`q_nb_wxyz`表示同一方向，四元数标量在前。
- 角速度以Body-FRD rad/s表达；位置m、速度m/s、加速度m/s²、角度rad、角速度rad/s、推力N、力矩N·m。
- `NavigationSnapshot.state_epoch/origin_id`是当前导航状态版本；M5/M6不得混用旧origin或旧state_epoch。

### 2. 平动LTI-MPC

固定结构：`nx=6`、`nu=3`、`Ts=0.02s`、`Np=20`、`Nc=5`、50Hz。状态`x=[pN,pE,pD,vN,vE,vD]^T`，输入`u=[aN,aE,aD]^T`。

对每轴使用零阶保持双积分器：

\[
A=\begin{bmatrix}I_3&T_sI_3\\0&I_3\end{bmatrix},\qquad
B=\begin{bmatrix}\frac12T_s^2I_3\\T_sI_3\end{bmatrix},\qquad c=0.
\]

目标函数固定为：

\[
J=\sum_{k=1}^{N_p-1}\bar e_{x,k}^TQ\bar e_{x,k}
+\bar e_{x,N_p}^TQ_f\bar e_{x,N_p}
+\sum_{k=0}^{N_c-1}\bar e_{u,k}^TR\bar e_{u,k}
+\sum_{k=0}^{N_c-1}\Delta\bar u_k^TS\Delta\bar u_k.
\]

其中`Q/Qf`为6×6对称半正定矩阵，`R`为3×3对称正定矩阵，`S`为3×3对称半正定矩阵。归一化尺度固定为位置1m、速度1m/s、输入加速度1m/s²、输入增量1m/s²；`e_x_bar=D_x^-1(x-x_ref)`、`e_u_bar=D_u^-1(u-u_ref)`、`Δu_bar=D_Δu^-1Δu`，因此权重无量纲。首版对角起始值：`Q=diag(8,8,12,3,3,4)`、`R=diag(0.8,0.8,1.0)`、`S=diag(0.2,0.2,0.25)`、`Qf=Q`。终端项只计一次；上述权重是SIL起始值，不是稳定性证明或实机整定值。

控制决策变量只包含`u[0..4]`；`k>=5`时保持`u[4]`至Np结束。`Δu[0]=u[0]-u_prev_command`，其中`u_prev_command`必须取M6快环最近一次经当前约束限制后接纳的MPC/备用加速度命令（不是实测PLANT加速度），而不是任意旧求解器变量。jerk约束采用线性输入差分盒约束`|Δu|<=j_max*Ts`。

首版约束全部按硬约束处理，不引入未定义松弛变量：M4 SafetyEnvelope和QUAD VehicleCapability给出位置/速度/加速度边界；倾角用8面内接正八边形约束，对`j=0..7`的法向量`n_j=[cos(j*pi/4),sin(j*pi/4)]`施加`n_j^T a_NE <= (g-a_D)*tan(theta_max)*cos(pi/8)`；推力上限采用保守线性内接盒`|g_n-a|_axis <= T_max/(sqrt(3)*m)`，由此保证三维范数不超过`T_max/m`，并由独立检查器对最终解再次验证真实范数；推力下限采用`g-a_D >= T_min/m`的保守线性下界。

悬停可行性必须在配置/PreArm检查：T_min/m≤g≤T_max/(sqrt(3)*m)，即该内接盒要求推重比至少sqrt(3)。CONTROL_MODEL检查失败返回CONTROL_REASON_MPC_HOVER_OUTSIDE_APPROX_DOMAIN；物理上可悬停但不满足盒约束的机型不能绑定该MPC Profile。T_max取当前电压/可用电机能力下的保守总推力，不以额定铭牌值掩盖退化。需要更合适的保守多面体时另走模型CR，不能静默放松真实范数约束。若硬约束不可行，拒绝本周期解，不得自动放宽安全包线。

当前外环使用 OSQP 1.0.0。源码、来源锁及 codegen 工具随 `mpc_solver/osqp/` 维护。Embedded mode 2 固定 15 个变量、190 行约束和稀疏模式，使用静态 workspace。迭代上限 80，绝对与相对容差 1e-3，求解设计预算 2 ms。ControlModelPort 的结构和函数以 02 为准，接口变更按 09 重跑 ABI 和消费者验证。`SOLVED_INACCURATE`只有在primal residual、dual residual及独立约束最大违反量均不超过1e-3（归一化单位）时可接受；否则按失败处理。求解状态至少区分SOLVED、SOLVED_INACCURATE、MAX_ITER、PRIMAL_INFEASIBLE、DUAL_INFEASIBLE、NUMERICAL_FAILURE、DEADLINE_EXCEEDED和INVALID_INPUT。

#### 2.1 QP、求解边界与私有交接

决策向量为5个3轴加速度，共15项；固定约束行依次为20步6维状态上下界120行、5步3维输入盒15行、输入差分15行、5步8个倾角面40行，共190行。不适用的状态界用合法±OSQP_INFTY，不改变稀疏模式。推力内接盒/垂向下界并入输入盒；真实范数独立检查。当前位置/速度不在可行域时不得靠无限界或删行掩盖故障。权重首版仅用所述对角阵；输入代价按Nc=5计，不对保持段再次重复加代价，归一化规则固定。

倾角变化会改变A的数值，因此不能用仅更新q/l/u的embedded mode=1；使用mode=2，关闭polishing和运行期heap，rho更新固定迭代间隔25，不依赖墙钟自适应。生成器/精度/静态RAM都须锁定；32KiB是07的接纳容量。OSQP 1.0.0 embedded 源码、生成的固定 workspace、QDLDL v0.1.8 依赖来源锁、许可证和 `generate_position_mpc.py` 均已纳入 `middleware/model/control/outer_loop/quad_x4/mpc_solver/osqp/`；运行期不使用 Python、动态内存或桌面 OSQP 库。当前分支 Cortex-M7 编译报告的 MPC 静态 RAM 为 29,400 B，MPC worker 栈为 8,192 B，最大单帧为 2,024 B；这是模块编译/资源静态证据，不是完整 H723 固件 RAM map、WCET 或实机证据。基于[OSQP代码生成定义](https://osqp.org/docs/codegen/index.html)选择此模式。

```c
typedef struct {
  ContractHeader header;
  uint32_t solve_sequence;
  uint32_t seed_control_sequence;
  uint32_t state_epoch, origin_id, reference_epoch, authority_epoch;
  uint32_t directive_epoch, envelope_epoch, model_epoch, safety_envelope_id;
  uint64_t solve_state_time_us;
  uint64_t solve_start_evaluation_time_us;
  uint64_t source_deadline_us;
  uint64_t expires_at_us;
  float acceleration_ned_mps2[3];
  float seed_position_ned_m[3];
  float seed_velocity_ned_mps[3];
  uint32_t solver_status;
} MpcOutputSnapshot;
```

该类型是M6私有交接，不新增跨模块公共业务消息。expires=min(授权/参考/包线/模型原截止、求解起始evaluation+20ms、publish+20ms、seed State Time+25ms)；导航种子TTL只在入口校验，快环继续用新鲜Nav复核，规则见本章MPC种子时效，不得因求解耗时而顺延；seed_control_sequence仅关联起始命令，不要求等于消费时最新快环序号。快环同时检查boot/time/state/origin/reference/authority/directive/envelope/model；约束或参考语义改变清除warm-start/旧输出。新参考事件可提前消耗本20ms求解预算，不能增加第二份CPU配额。

快环对MPC或PD候选都重新施加当前加速度/jerk/倾角/推力约束；jerk使用实际State Time间隔，不以20ms代替1ms。限幅后的加速度才更新u_prev_command；Receipt只作命令级抗饱和证据，不把它当作实测加速度。

### 3. 推力向量与期望姿态构造

NED重力向量`g_n=[0,0,g]^T`，期望加速度`a_d`对应：

\[
v_T=g_n-a_d,\quad T=m\|v_T\|,\quad b_{3d}=v_T/\|v_T\|.
\]

期望航向`psi_d`定义为NED平面从North向East为正，构造`b_{1c}=[cos(psi_d),sin(psi_d),0]^T`，随后：

\[
b_{2d}=\frac{b_{3d}\times b_{1c}}{\|b_{3d}\times b_{1c}\|},\qquad b_{1d}=b_{2d}\times b_{3d},\qquad R_d=[b_{1d}\ b_{2d}\ b_{3d}].
\]

当叉积范数低于配置退化门限时，先将上一有效`b2`投影到与`b3d`正交平面；投影仍退化则使用确定性备用轴并置`ATTITUDE_BASIS_DEGRADED`。任何归一化前均检查有限值和最小范数，禁止NaN/Inf进入姿态环。

### 4. SO(3)姿态误差与角速度环

定义相对旋转`E=R_nb^T R_d`，姿态误差为完整主值对数映射：

\[
e_R=\operatorname{vee}(\operatorname{Log}(E)).
\]

期望机体系角速度为：

\[
\omega_d^d=\operatorname{vee}(R_d^T\dot R_d),\qquad
\omega_{sp}^b=R_{nb}^TR_d\omega_d^d+K_Re_R.
\]

`R_d^T dot(R_d)`必须由期望姿态连续差分/解析导数得到，并以期望机体系表达；不得把偏航角速度单独当作完整三轴期望角速度。离散实现固定为ω_d^d[k]=-Log(R_d[k]^T R_d[k-1])/dt，dt取相邻State Time差；首帧/epoch切换前馈为0，非正dt拒绝。微小角阈值1e-6rad使用泰勒式，π邻域阈值1e-4rad使用对称轴提取；归一化最小范数1e-9。跨越±π前先连续展开偏航参考。

不得再把`0.5*vee(R_d^TR_nb-R_nb^TR_d)`称为完整SO(3) Log映射；该反对称表达仅与`sin(theta)`相关，在接近π时会退化。Log实现必须定义主值分支：接近π时从(R+I)/2最大对角分量提取轴；轴符号优先与上一有效轴点积为正，否则按固定lexicographic规则；精确π分支不得除以sin(theta)。必须测试±179.9°、180°、±180.1°、任意轴π旋转、q与-q等价、重构误差和Yaw跨界。

### 4.1 Rate PID和PD备用的唯一离散律

每轴令e[k]=ω_sp[k]-ω_meas[k]，先对测量差分d_raw=(ω_meas[k]-ω_meas[k-1])/dt作一阶低通，α=exp(-2π f_c dt)，d[k]=α d[k-1]+(1-α)d_raw。输出τ_req=Kp*e+I-Kd*d；I[k+1]=clip(I[k]+Ki*e*dt+Kaw*(τ_alloc_est-τ_req)*dt,±I_limit)。Kp/Ki/Kd/Kaw及积分上限单位由02配置字段定义；不能对误差微分造成设定跳变冲击。首帧导数为0；模式/epoch重置令I=0并重新限速设定；任何非有限结果拒绝本周期输出。dt允许范围及样本gap按05/07，不固定写1ms。

位置备用固定a_cmd=a_ref+Kp_pos*(p_ref-p)+Kd_pos*(v_ref-v)，无积分；与MPC共用当前全部约束和相同参考插值器，约束无可行解则拒绝Demand，不能把“限幅”称为可行。仅有垂向能力时只允许ALT_HOLD/经许可垂向降落通道，水平由授权人工姿态/角速度控制；M5/M6不生成虚构XY位置保持。无姿态/角速度能力则不执行该备用。

手动RATE将授权轴映射到SafetyEnvelope的body-rate上限、throttle映射到配置推力曲线；手动ATTITUDE由M5产生归一化q，M6仍走SO(3)+Rate PID。ALT_HOLD必须有垂向位置/速度能力；不能因缺水平定位要求完整XYZ MPC。所有切换先使旧参考/积分无效，再接纳新epoch，地面IDLE不调用闭环。

### 5. Rate PID、控制分配和M7物理接口

- M6 Rate PID输出机体系力矩`tau[N·m]`；增益必须按物理单位定义。旧版“归一化输出域”增益不得直接沿用，必须换算/重新整定并通过SIL。
- X4 allocator输入`[T,tau_x,tau_y,tau_z]`，输出四路N单位推力。M7执行标定/编码，PLATFORM驱动独占TIM/DMA。DShot启动、DMA长度和零尾只引用07的唯一时序，不在控制文档复制寄存器计算。实际波形验证前不能标记输出通过。

**1kHz控制与400Hz DShot帧刷新契约：** M6每次快环计算只发布带`control_sequence`、`header.timestamp_publish_us`、`demand_expires_at_us`和Permit关联Epoch的最新`ActuatorDemand`快照；M7/PLATFORM不得排队发送所有中间Demand，只在每个TIM2_CH1帧边界原子采样最新且未过期、Permit有效的Demand，执行零阶保持至下一帧。帧边界无有效Demand时执行产品定义的安全输出，不复用已过期命令。PLATFORM驱动将实际帧提交事件报告给M7，M7按02唯一发布公共`ActuatorCommitReceipt`；M6通过ControllerInput只读消费，在固定8项请求历史中匹配applied_control_sequence和关联epoch。Receipt只证明命令提交，不能要求它等于当前1kHz最新序号，也不能直接访问驱动私有缓存。M6原有Rate PID抗积分饱和主路径仍使用`allocator_achieved_wrench_estimate - requested_wrench`模型估计残差；若M7物理限幅/变化率使已提交命令进一步偏离M6 Demand，则M6可用Receipt.committed_demand的命令等效推力和同一效能矩阵计算`output_limited_wrench_estimate`，作为附加命令级抗饱和反馈，不得称为实测力/力矩。当前ESC反馈能力为NONE，因此Receipt只证明命令已提交，不代表实际转速/推力。
- X型布局使用参数化臂长`l`。Body-FRD位置可定义为M1前左`(+l/√2,-l/√2,0)`、M2前右`(+l/√2,+l/√2,0)`、M3后右`(-l/√2,+l/√2,0)`、M4后左`(-l/√2,-l/√2,0)`。该编号只用于通用SIM_ONLY模型；实机电机编号/旋向必须按实际线束和电机方向映射。
- 分配矩阵按每个旋翼位置`r_i=(x_i,y_i,0)`、推力系数`k_f`、反扭矩系数`k_m`及经确认的yaw torque sign`gamma_i`生成：

\[
\begin{bmatrix}T\\\tau_x\\\tau_y\\\tau_z\end{bmatrix}
=\begin{bmatrix}
1&1&1&1\\
-y_1&-y_2&-y_3&-y_4\\
x_1&x_2&x_3&x_4\\
\gamma_1&\gamma_2&\gamma_3&\gamma_4
\end{bmatrix}
\begin{bmatrix}f_1\\f_2\\f_3\\f_4\end{bmatrix}.
\]

其中`gamma_i`单位为m，等于带符号的`k_m/k_f`；旋向符号不能仅凭X型名称推断。分配器必须输出饱和标志、`allocator_achieved_wrench_estimate`、各轴估计残差、`roll_pitch_scale/thrust_scale/yaw_scale`和有效电机mask；该wrench是由分配器命令和车辆模型计算的估计值，不是实测物理推力/力矩。QUAD首版`ESC_FEEDBACK_CAPABILITY=NONE`，不得把估计wrench描述成电机实际反馈。有效电机mask只表达配置/输出链路已知可用性，不得冒充单电机失速检测。上下限/变化率来自ActuatorCapability。M7不做控制分配。

**QUAD_X4饱和优先级唯一为：横滚/俯仰稳定力矩 > 总推力跟踪 > 偏航力矩。** 电机上下限和变化率是不可违反的硬约束。出现饱和时按固定顺序处理：①首先将偏航力矩向零方向缩减到可行范围；②在保持横滚/俯仰力矩的条件下，将总推力调整到可行区间内最接近请求值的位置；③仍不可行时，对横滚/俯仰力矩向量作统一比例缩放，取满足全部电机硬约束的最大可行比例；④若上述缩放域为空，而最近一次成功分配的导航 boot/time/state/origin 一致、年龄≤25 ms 且仍满足本周期硬约束，以其电机向量为基点，对请求增量按同一优先级再求解一次；⑤仍无可行解、有效电机矩阵秩不足或数值求解失败时，输出`ControlCapability.reason_code=CONTROL_REASON_ALLOCATOR_INFEASIBLE`或`CONTROL_REASON_ALLOCATOR_RANK_DEFICIENT`（数值定义唯一见02号文件`ControlReasonCode`），同步更新可控自由度mask/health state，不得逐电机独立Clamp后伪装成功；M4依据降级能力和安全策略处置。每一步的比例/推力调整必须由固定大小、有限步的区间求交/边界求解实现，禁止动态分配和无界迭代。Rate PID anti-windup必须使用`allocator_achieved_wrench_estimate - requested wrench`模型估计残差；不能将其称为实测执行器反馈，也不能只依据电机命令是否触顶。该优先级是QUAD_X4首版控制分配策略，不自动推广到UGV/USV。

### 6. 快环频率和失败行为

控制时间对齐见下一节；1kHz/50Hz交接、TTL、fallback及M7守卫在本章对应条款直接定义。

### 6.3 M3导航状态与M6控制评估时刻对齐（规范性）

- M3是状态估计器（Estimator），M6是反馈控制器（Controller）；两者之间传递带时间戳的状态快照，不共享或访问对方内部滤波器/控制器状态。
- M6每次快环必须选择一个唯一`control_time_us`，并确保`NavigationSnapshot`状态时刻和`MotionReference/PilotControlReference`评估时刻一致。首版`control_time_us`取本次被消费导航快照的`header.timestamp_sample_us`。
- 参考轨迹必须按`control_time_us`插值；MPC 50Hz的初始状态与预测参考也必须同一时刻对齐。`T_act`仅做执行延迟预瞄，不允许将状态时间戳向未来改写。
- M6不得私自对NavigationSnapshot做常速度、常角速度或经验外推。若未来需要预测到控制/执行时刻，必须由M3提供带目标时刻、预测时长、协方差增长、模型版本和TTL的预测状态接口，并通过CR审批。
- M6必须校验`boot_id/time_epoch/state_epoch/origin_id/reference_epoch/authority_epoch/directive_epoch`及TTL。时间轴不一致、数据过期、参考插值越界或时间不确定度超限时，拒绝本周期输入并发布稳定reason code；M4按安全策略决定降级。
- M6记录`state_to_control_age_us`、`reference_alignment_error_us`、`control_compute_us`和`control_to_actuator_latency_us`；M7/PLATFORM记录实际输出帧启动/完成时刻。所有统计进入07/09统一验收，不在多个文档重复维护门限。


M6 Fast Control以每个有效IMU/NavigationSnapshot更新事件运行，最高1kHz；首版SO(3)与Rate PID均在该快环执行，MPC独立50Hz。M7输出守卫由新Demand事件和独立1kHz安全唤醒共同驱动；即使无新Demand也必须检查Permit/Demand TTL、M6 heartbeat、control_sequence单调推进、Timer/DMA状态和当前输出策略。DShot物理波形由TIM/DMA硬件完成，实际bit rate为DShot300或DShot600，帧刷新时序取实际TIM配置/ESC约定，不得把300/600kbps误写成控制环频率。

MPC 50Hz任务只通过`MpcOutputSnapshot`双缓冲向1kHz快环交接；快环不得等待求解器或读取其内部workspace。Snapshot字段以本章MpcOutputSnapshot为准，包含完整上下文和原输入截止，不能把私有solve_sequence冒充快环control_sequence。快环只接受Epoch完全匹配且TTL覆盖当前控制周期的完整快照，采用零阶保持；单次失败最多保持一个MPC周期（20ms），不得无限延长。

MpcOutputSnapshot.expires_at_us固定取本章2.1定义的三个截止最小值；它在原TTL内最多保持一个MPC周期，失败不能续写旧结果延长TTL。无匹配新结果且旧结果已过期的当个快环立即使用已验证的限幅PD备用平动控制，不等待“第二次失败”造成空窗；备用控制要求位置/速度/姿态能力有效。连续两次失败发布BACKUP_ACTIVE/控制退化，连续五次失败或导航不可观测由M4按剩余能力响应。姿态/角速度状态失效时不得继续声称位置保持能力；M7只执行本地许可/输出保护，不代替姿态控制。

### 6.1 M7 输出失效策略冻结规则

首版策略注册固定：0 UNSUPPORTED（拒绝PreArm）、1 BENCH_INHIBIT（硬件输出保持禁止、仅诊断）、2 SIM_CONTROLLED_STOP（仅Host Plant按仿真模型受控停止）。当前H723默认1，Host/SIL可用2；不得把2用于实机。实机飞行策略ID从0x0100起，只有完整的stale/Permit撤销/失效/复位状态表和目标证据齐全才能登记，否则物理执行器能力为不可用。此处固定默认行为，不留下“实现者自行选择SAFE_ACTION”的分支。

#### 6.1.1 M4→M7 GroundStopCertificate 当前实现边界

M4 仅在 `SIM_CONTROLLED_STOP`（策略 2）的 Host/SIL 路径上签发地面停机证书。当前 `fms_build_ground_stop_certificate()` 要求同一 FMS 输出中的 Permit 为新鲜、M4 来源且已撤销，DecisionEvent 与 Permit 的 boot/time epoch 匹配，`landed_state=LANDED`、`arm_state=DISARMED`，并且决策原因是首次参考超时地面上锁或显式 Disarm。它不把空中 failsafe Permit 撤销转换为 ramp。当前 producer 固定发 `lifecycle=LANDED` 和 200 ms 租约；M7 guard API 虽接受 `LANDED/DISARMING` 两种枚举，DISARMING 证书当前并未由 FMS producer 发出。

`task_mission_step()` 将证书随 ControlBundle 传给 M7；当前 FMS 输出明确不符合条件时清除缓存证书，没有新 FMS 输出时也只保留原证书租约。`task_actuator_step()` 先调用 `actuator_guard_ground_stop()`，只有 guard 接受后才让该事务独占后续帧并抑制待处理 M6 Demand。M7 在帧边界执行有界单调 ramp，DShot 由 DMA 异步发送；`actuator_poll()` 轮询帧完成后发布 receipt，只有零目标 receipt 才锁存 DISARMED。Host/SIL 集成测试覆盖此软件链路；H723 当前仍为策略 1 `BENCH_INHIBIT`，不具备该物理输出路径，不能把软件测试描述成实机受控停机。

M7 本地状态至少区分 DISARMED、ARMING_IDLE、ACTIVE、HOLD_GRACE、SAFE_ACTION、FAULT_LATCHED。QUAD首版`ESC_FEEDBACK_CAPABILITY=NONE`，不得宣称直接RPM/单电机失速检测；输出链路故障、执行器响应可疑和执行器故障确认必须分级，证据不足时为UNKNOWN/UNOBSERVABLE。M7 只按 Permit 中的`output_policy_id`查找编译期产品策略，不接受任意自由文本策略。

- DISARMED/地面停机：只有地面状态被独立确认时才允许受控 ramp-to-zero/disarm。
- 单次Demand迟到：只允许在原Demand TTL、有效Permit和policy最大hold时限三者的最早截止前保持；不重新发布或延长旧Demand。到期执行已批准的产品SAFE_ACTION；没有产品策略时PreArm拒绝。
- Permit 过期：拒绝新的 Demand；不得把过期 Permit 当作持续授权。
- 空中 M6 heartbeat 丢失、Timer/DMA fault、MCU reset：不存在跨产品通用的“电机归零即安全”策略。必须由产品危险分析定义独立安全动作/硬件保护/备用控制，并经 HIL 验证。
- `output_policy_id=UNDEFINED/UNSUPPORTED` 时，PreArm 必须拒绝解锁。当前项目尚无已核验的硬件 Kill/BKIN 证据，空中终态策略属于飞行放行安全审查项，不阻止当前软件设计与实现；不得宣称已解决。

### 7. M5局部地图、A*容量、超时和minimum-jerk

**验证适用矩阵：** `OBSTACLE_SOURCE_MODE=NONE`只允许不要求避障保证的普通点到点/位置保持/返回任务；M4必须在任务元数据中明确`requires_obstacle_avoidance=false`并向遥测声明`OBSTACLE_ASSURANCE_UNAVAILABLE`。M5仍强制执行时间、epoch、动力学、参考连续性及适用围栏检查，障碍几何项为`NOT_APPLICABLE_BY_PROFILE`，不能生成全FREE地图或报告碰撞检查PASS。要求避障的任务在NONE下直接拒绝。STATIC_MAP/SIMULATION/ONBOARD_SENSOR任务一旦依赖障碍源，全部未知/失效规则和连续碰撞验证必须生效；源失效不能运行时降成NONE继续原避障任务。真实飞行是否允许普通无避障任务由产品危险分析/用户放行决定，当前仍未放行。

历史QUAD静态地图测试夹具固定16×16×16=4096 cells、0.5m/cell；实机OBSTACLE_SOURCE_MODE=NONE；cell状态UNKNOWN/FREE_CONFIRMED/OCCUPIED_CONFIRMED/STALE/INVALID；log-odds范围[-32,32]，free更新-2、occupied更新+4，阈值free≤-4、occupied≥+4；500ms无有效更新转STALE；动态障碍track最多8条，Host合成源预测界至少1s；真实障碍源未接纳，不声明实物预测能力。UNKNOWN/STALE/INVALID/地图外均不可视为自由空间。动态预测超出其经过验证的有效窗口按UNKNOWN处理；不能在预览尾部假定安全。局部栅格以当前NavigationSnapshot位置为中心，中心按0.5m整数格滚动；滚动时按世界坐标保持重叠cell，新暴露区域清为UNKNOWN，单轴位移达到8m则整图清空并重置中心。地图坐标仍为同一LOCAL_NED，不随滚动改变frame/origin/state epoch。A*必须按每条边的绝对到达时刻检查cell有效期；不得仅在规划起始时刻检查一次并将FREE状态外推到过期时刻。

Kinodynamic A*的规范状态键为(voxel12bit,velocity5bit,yaw4bit,time_bin5bit)，key=(voxel<<14)|(velocity_bin<<9)|(yaw_bin<<5)|time_bin；其余高6bit为0。time_bin以本规划起始State Time为0，步长0.2s，最大31（6.2s）。等待边到新time_bin，不可被同位置/速度/航向的旧节点合并。动态验证使用该绝对到达时刻；重采样/平滑后再次验证实际消费曲线。

除根节点外，p严格为网格中心、v为本节速度bin表的精确向量、yaw=2π*yaw_bin/16、a=0。根节点额外存实际导航p/v/a/yaw，不把当前位置吸附到网格；首条quintic从实际根状态连续连接到规范端点。每个候选端点先取最近网格中心，再用完整quintic验证连接；不允许先传播再仅修改key而丢失连续状态。达到目标需落在任务acceptance_radius内且满足末端速度/航向条件，不能瞬移到航点。

60项primitive表按如下算法唯一生成，记录为(kind:u8,dir:u8,speed_id:u8,duration_id:u8,target_speed:f32,yaw_rate_hint:f32,duration_us:u32)，16B/项，64项表后4项全零。P00–31按dir=0..7、speed=0.5/1.0、duration=0.2/0.4的嵌套顺序，dir从北顺时针每π/4；P32–39按N/E/S/W和0.2/0.4s，速度2.0；P40–47按UP/DOWN、速度0.5/1.0、0.2/0.4s；P48–55按左/右、yaw-bin变化1/2、时长0.4/0.8s（禁止将0.1rad等非lattice终态仅取整丢失）；P56/57等待0.2/0.4s；P58/59以0.2/0.4s制动到零速度。位置终点初值为p_start+0.5*(v_start+v_end)*T，取最近网格中心，精确半格按较小voxel索引；Yaw原语位置终点按同规则，速度目标保持原bin。速度bin方向/编号：0静止，1..24为dir0..7各0.5/1/2m/s，25/26为UP0.5/1，27/28为DOWN0.5/1。

所有边从端点p/v/a/yaw约束解唯一五次系数，实际曲线的速度/加速度/jerk/推力/倾角超限即剔除。g为累计秒数，h=max(到目标接受球距离/v_max,最小yaw角差/yaw_rate_max)，均忽略加速度约束形成可采纳下界；f=g+h，不加未定义权重。比较按(f,h,key,NodeID)，改善g超过1e-6s才重开。

Node Pool512、Open512、每请求最多512扩展、每节点最多64边检查。Node16B仍为key:u32,g:f32,f:f32,parent:u16,heap_index:u16。1024个uint16哈希索引用2654435761u乘法和线性探测，最多1024次；比较完整含time的key。Closed按NodeID共64B；容量耗尽、time_bin越界或路径超过8个可连续段时返回明确容量/期限错误，不截断成成功。primitive manifest 的实施落点为 `config/kinodynamic_primitives.yaml`，由 `tools/guidance/generate_kinodynamic_primitives.py` 确定性生成 `kinodynamic_primitives_generated.h`，CI 必须执行 `--check` 防止手工表与规范漂移。M5-02 Local Map 与 M5-03 A* 内核仅在 `FLIGHT_M5_HOST_PLANNER` 下编译；H723/NONE 构建不编入这些源文件、不分配地图/A* arena。当前 Host/SIL 单元测试不代表 H723 实时性、实机障碍源可用性或 M5-06 连续碰撞验证通过；启用实机避障仍须独立 CR、资源复核、M5-06 验证和 HIL/飞行放行。该文件不属于 08 号“四份 CORE 调参”。

Planner Worker的H723试验上限仍为每slice≤300us、每100ms累计≤300us，但首版H723/NONE不编入地图/A*；Host/SIL不沿用该目标CPU速率来声称实时成功。H723未来开启地图必须重新接纳07资源组合；请求必须有绝对`planning_deadline_monotonic`。错误码分开：`NO_PATH`（搜索完成无路）、`PLANNER_CAPACITY_EXCEEDED`（节点/候选容量耗尽）、`PLANNING_DEADLINE_MISSED`（截止时间到）、`INPUT_STALE`（地图/导航过期）、`OPTIMIZATION_FAILED`（minimum-jerk失败）、`TRAJECTORY_REJECTED`（M5-06验证不通过）。部分路径不得作为成功发布。

轨迹平滑唯一采用固定时间 minimum-jerk quintic spline，最多8段；分段时间由下述有界时标器确定，内部knot位置固定，内部knot速度/加速度为唯一优化变量，目标为 `J=Σ_i∫_0^{T_i}||p_i'''(t)||²dt`。不做运行时联合时间优化，不加固定时间下无作用的时间正则项，不使用未定义走廊软惩罚。固定维数带状SPD系统求解，静态workspace；优化失败只允许使用同一路径、重新通过M5-06验证的初始五次轨迹，否则规划失败。

时标器不再留未定义的S-Curve选项：M5-04先取每段T=max(0.2s,d/v_lim,sqrt(d/a_lim),cbrt(d/j_lim))向上取0.2s格；构造端点quintic后用向外取整的Bernstein系数界检查各轴v/a/jerk，并同时检查三维速度/加速度范数和yaw-rate上界（取max_yaw_rate与max_angular_rate较小值），不满足则T*=1.25并上取格，最多16次且总时长≤6.2s。无可行时长即拒绝，不无限延长。`m5_time_scaler_build` 接收完整M5AstarPath、当前导航和有效SafetyEnvelope，输出M5TimeScaledPath；A* primitive时长只作为输入路径合法性/初始时间依据，时标器重新计算每段时长并记录attempts。M5-05固定这些时长执行minimum-jerk优化：内部knot位置固定，内部速度/加速度为优化变量，目标为J=Σ∫||p'''(t)||²dt，采用固定workspace带状SPD分解。`m5_path_smoother_build` 只接收map_revision匹配、地图仍有效且knot仍位于FREE cell的M5TimeScaledPath，输出固定段数position/yaw quintic候选；优化失败时只允许输出同一路径的初始quintic并显式标记FALLBACK。该输出不是MotionReference，不得发布；M5-06独立验证通过前不可交给M6。

H723/NONE使用直接有界quintic与围栏验证，不分配A*/地图arena；Host/SIL使用完整地图/时空A*。动态预测必须覆盖整个[参考t0,t0+480ms]再加有效观测年龄/不确定度窗口；Host合成源固定至少1s预测界。旧300ms仅能导致拒绝，不能用于480ms参考验收。ONBOARD_SENSOR当前不支持，不能自行扩大预测上限声称有实物保证。

#### 7.1 M5-06 独立轨迹/连续碰撞验证器（规范性）

M5-06 是轨迹发布前的独立硬约束验证子模块，不与 A* 搜索代价或minimum-jerk优化目标合并。输入为含anchor+24未来点的候选 `MotionReference`及02定义的唯一Hermite插值器、当前及有效期内的 `ProductObstacleObservation`/局部地图、`ProductGeofenceSnapshot`、导航 Epoch、VehicleCapability/SafetyEnvelope 和当前 monotonic time；输出只能为 `VALID` 或带稳定 `GuidanceReasonCode` 的 `REJECTED/UNKNOWN`，reason code 唯一见02号文件 `GuidanceReasonCode` 注册表。`UNKNOWN` 对 M4/M6 的处理必须 fail-closed，等同拒绝该参考，不得作为降级通过。M5 不得将未完成验证的部分路径、优化中间结果或过期地图结果发布给 M6。

验证规则：

1. **车辆包络：** 使用经产品验证的保守车辆外接球/胶囊体或等价固定凸包；几何近似必须不小于真实机体/桨盘危险包络。
2. **静态障碍：** 对轨迹曲线段与障碍点/球/AABB执行膨胀后的几何相交检查；障碍物按车辆包络半径、几何安全裕度、导航/感知不确定度及反应延迟距离保守膨胀。
3. **动态障碍：** 将障碍物预测位置与车辆轨迹按同一 monotonic 时间轴对齐，采用相对运动检查；只使用有效时间窗内的速度/不确定度，超出预测有效期按 UNKNOWN/保守占据处理。
4. **连续性证明：** 不能只检查固定采样点。对每个轨迹区间执行 swept-volume 几何检查；若实现采用有界自适应细分，则在区间中点计算有符号净空 `c_mid`，并以经验证的相对速度/加速度上界计算区间内最大可能位移 `b = v_rel_max·Δt/2 + 0.5·a_rel_max·(Δt/2)^2`。只有 `c_mid - b > 0` 才能证明该区间无碰撞；否则继续二分。若速度/加速度上界缺失、无法形成保守下界或达到最大细分深度仍不能证明安全，必须拒绝，不得把“未采样到碰撞”当作安全。
5. **不确定度与延迟：** 位置/速度标准差必须经产品批准的保守系数转换为几何膨胀；`confidence_0_to_1`仅为质量分数，不等于概率。总延迟至少包含测量年龄、传输/融合、规划、控制和执行器响应延迟；延迟期间按相对运动继续膨胀。所有安全裕度和系数必须进入 Product Profile Hash；未标定时保持 `SOURCE_EVIDENCE_PENDING`，真实飞行 Profile 不得启用障碍源。
6. **地理围栏：** 对整条连续轨迹段检查 Keep-in/Keep-out 多边形边界和高度区间，不得只验证航点；围栏无效、TTL过期、frame/origin/state_epoch不匹配、自交/退化多边形或容量超限时拒绝依赖该围栏的任务。
7. **未知空间：** UNKNOWN、STALE、INVALID、地图外、REJECT源和时间不确定度超限均不得解释为 FREE。
8. **固定资源。** 原始优化器最多 8 段，实际消费曲线固定 24 个区间。消费区间细分深度最多 5，单次验证最多访问 256 个父子区间。待处理区间用深度优先栈，按时间从早到晚访问。栈最多同时保存 29 项，单项保存区间号、深度和归一化时间界，当前 ARM 工作区为 348 B。全段围栏验证复用该栈，单根深度最多 7。访问预算或容量耗尽时拒绝轨迹。实际 WCET 纳入 M5 预算，静态占用见 07。

速度/加速度上界由消费插值多项式在当前子区间的Bernstein系数凸包界给出；障碍物按有效预测窗口的界叠加。缺少界或预算耗尽即拒绝，连续证明必须覆盖实际24区间。

其中`c_mid`必须是轨迹中点到障碍物几何的有符号净空，且障碍物几何已按车辆包络、产品安全裕度、不确定度和反应延迟膨胀；`v_rel_max/a_rel_max` 必须是整个区间内经产品模型/感知预测保证的相对速度/加速度上界，而非中点瞬时值。任一上界无法证明时，区间不能认证安全，必须继续细分或拒绝。

本节是 M5-06 的唯一算法定义；资源预算见07，09号文件定义测试证据。

地图窗口8m不是任意速度下的安全视距。Profile必须满足：

\[
d_{required}=\frac{v^2}{2a_{brake,min}}+v t_{latency}+d_{margin}.
\]

当`d_required`超过可用地图/感知视距时，M5必须限速或拒绝任务。`a_brake_min`、`t_latency`、`d_margin`和实际速度上限当前均为SIM_ONLY/待实机标定，不得伪装为实测值。

### 8. QUAD模型状态

第一版采用通用X型四旋翼Plant/ControlModel；质量、重心、惯量矩阵、臂长、旋向、推力/反扭矩系数、电机时间常数均进入`vehicle_model.yaml`，当前样例必须标记`SIM_ONLY`。Host/SIL可使用明确的合成参数完成闭环；在实际上机标定前，QUAD Profile不得标记为`FLIGHT_RELEASE_PASS`。

### 9. 人工/定高参考与固定数据边界补全

MANUAL_RATE的ω_sp为三个[-1,1]轴分别乘有效SafetyEnvelope角速度上限，yaw前馈不得重复相加。MANUAL_ATTITUDE将roll/pitch输入组成倾斜旋转向量，范数裁至max_tilt；yaw按授权yaw_norm*max_yaw_rate以实际State Time间隔积分，初值为进入模式时有效航向。R_d=Rz(yaw)*Exp([roll_tilt,pitch_tilt,0])，由M5转为归一化q，首帧不使用未初始化yaw。手动总推力意图采用唯一三点映射：x=throttle_norm，h=manual_hover_throttle_norm，x≤h时T=Tmin+(mg-Tmin)*x/h，x>h时T=mg+(Tmax-mg)*(x-h)/(1-h)；须0<h<1且Tmin≤mg≤Tmax，最终仍经过当前包线/分配器。M7每电机推力→DShot标定曲线不负责解释飞手摇杆。

有效 Home 高度作为当前平坦着陆场景的参考平面。位置降落及返航先到达平面上方 0.6 m 的对准点。对准参考到达终点、机体水平误差不超过 0.30 m、水平速度不超过 0.25 m/s、垂直误差不超过 0.20 m 且垂直速度绝对值不超过 0.20 m/s 时，接续垂直末段。已在对准高度内开始时直接验证末段。进入平面上方 0.5 m 时，下降参考速度限于 0.35 m/s。规划段和实际消费的 Hermite 段均按连续上界验证，保留已有速度、加速度、jerk、围栏和倾角约束。该参考平面仅适用于已确认的平坦仿真场景。实物近地减速需要有效 AGL 或着陆点高度证据。缺少水平定位的垂向备份继续按对应安全策略处理。

在 Host/SIL Profile 内，连续的轨迹模式交接使用当前导航位置和速度，并从上一周期仍有效且处于 ACTIVE 的已验证轨迹采样起始参考加速度。同一 boot/time/state/origin、State Time 递增且交接间隔不超过 40 ms 才可采样。实际导航加速度有效且范数不超过 6 m/s²。新指令生成独立 reference 和 permit；新曲线仍按全部连续约束复核。跨 epoch、无有效前参考或过大实测冲击时，按当前导航状态建轨并执行原验证。

ALT_HOLD按02的ALTITUDE_ATTITUDE typed参考：a_D_cmd=-kp_z*(h_sp-h)-kd_z*(v_up_sp-v_up)，T=m*(g-a_D_cmd)/R_d(2,2)。R_d(2,2)必须≥cos(max_tilt)>0；最终T/力矩/单电机范围及slew全部可行才发布。无水平导航时不用XYZ MPC或水平PD；不能从空MotionReference取高度。所有高度为Origin相对、Up正；相对Home任务显式转换后重建参考。

Node parent不足以复现同一端点间不同primitive，固定额外512×uint8 parent_primitive表512B放planner scratch；根节点parent=0xFFFF、primitive=0xFF。哈希empty=0xFFFF，slot保存NodeID并用node.key全键比较；hash=((key*2654435761)mod2^32)>>22。Open heap存NodeID，比较(f,h,key,NodeID)，h=f-g；reopen清Closed、更新g/f/parent/parent_primitive并decrease-key。WAIT仅v=0且同位置，非零速度用BRAKE再等待；yaw primitive保持速度bin且端点yaw严格格化，yaw quintic端点rate/accel=0，普通平移保持yaw。根节点v/yaw不在格时，只用实际状态生成连续首边，末端才进入lattice。

MapCell固定8B：log_odds:i8、state:u8、source_mask:u16、last_update_ms:u32；每次读先按TimeService epoch及age求STALE，uint32毫秒半范围比较，窗口<2^31ms。64B动态track包含id:u32、source_id:u16、flags:u16、sample_us:u64、expires_us:u64、position[3]/velocity[3]:f32、radius/position_std/velocity_std:f32、reserved:u32；全部epoch放该地图上下文，跨epoch整体清空。地图/world-grid变换原点、每轴cell中心和边界均固定到规划请求快照；换窗时重新规划，不复用旧key。

静态地图Host基准世界范围为每轴[-4m,4m)、cell中心=-3.75+0.5*i（i0..15），voxel=(iz*16+iy)*16+ix。超范围目标/末端不能靠部分路径伪装成功；长距离任务需M4显式分段且每段满足当前窗口和6.2s搜索域，否则OUT_OF_RANGE。局部移动窗口未来扩展必须作为新的map context/revision整体重建，不继承当前静态夹具坐标。

### 10. MPC种子时效与快环复核

MPC求解入口的NavigationSnapshot必须满足5ms新鲜度，但其Header.valid_until不直接充当20ms零阶保持的截止。`source_deadline_us`固定只取Reference/GuidanceStatus、Directive、Permit、Authority、SafetyEnvelope与Model快照原截止的最早者；Nav是求解种子，另受`MPC_SEED_MAX_AGE_US=25000`限制。最终expires=min(source_deadline,solve_start_evaluation+20000,publish+20000,solve_state_time+25000)。所有截止先检查boot/time，不能无符号溢出；在原授权截止之外不因续租延长旧解。

快环每次仍读取新鲜Nav，核对seed上下文（允许普通Nav.sequence推进），并与种子模型轨迹比较：p_pred=p_seed+v_seed*dt+0.5*a_hold*dt²，v_pred=v_seed+a_hold*dt，dt=当前State Time-seed State Time。误差任一轴超过Controller配置的mpc_seed_position_error_limit_m或mpc_seed_velocity_error_limit_mps则立即拒绝旧解、清warmstart并切同约束PD。此预测仅用于检查MPC适用域，绝不替代或回写M3 Nav。上述阈值为CORE整定且必须>0，未验证时只允许Host fixture，不能任意设大绕过。

ControlModel/Controller/Plant的平动p/v固定为CG参考点，旋翼位置r_i也相对CG。M6消费M3已转换的CG导航状态，不在控制器重复加IMU杆臂。
