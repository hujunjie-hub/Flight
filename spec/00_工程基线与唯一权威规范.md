## 3. 系统约束

- UM982 是主要必装器件，`GNSS_SUPPORT=1`、`GNSS_PPS_CAPTURE=1`。UART4 RX DMA 和 TIM2_CH3 PPS 固定接入。PVT、链路、PPS 和 UTC 分别判定，启动获星前或运行期信号中断时继续使用本地 TIM2、IMU 与 INS。水平导航模式按剩余能力准入，恢复后由 M4 重新评估授权。
- M3 发布导航状态和能力，M4 拥有任务、权限和 Permit，M5 生成并验证参考，M6 计算需求，M7 在帧边界复核并提交。外部命令通过 M4 仲裁，模式和失败行为以 06 为准。
- H723 的障碍源为 `NONE`，受已验证的围栏和全段轨迹约束。地图 A* 属于 Host/SIL 扩展，板端启用需要重新核算容量和时序并取得证据。
- 未取得产品参数、硬件能力或安全证据时，按 08 标记缺失能力并拒绝依赖它的模式。物理输出策略与实物放行由 09 验收。
- `doc/Flight.xlsx` 是硬件配置输入，板级源、原理图、寄存器及目标测量用于确认实际绑定。差异按 07 处理。

## 4. 接口与依赖基线

- Schema 6.0 与旧 Major 隔离。公共 C 布局与 MAVLink 线格式各有独立验证，字段和 CRC 来源见 02 与 `contracts/FCU.xml`。ABI 指纹由 `tests/abi/abi_report.py` 生成。
- 固件复用现有 RT-Thread、BSP、HAL/CMSIS 和根 SCons/Kconfig。包含公共契约的 GNU Arm 编译单元统一使用 `-fno-short-enums`，构建详情见 03。
- `packages/deps.lock` 汇总依赖，KF-GINS 和 OSQP 分别由 INS 与控制外环维护完整来源、源码或生成件、补丁、许可证和版本锁。H723 KF-GINS 使用裁剪内核的固定维数矩阵。OSQP 固定使用 1.0.0 生成的静态工作区，生成参数及求解失败行为见 04。
- 发布记录实际工具链、配置、源码和产物 SHA256、依赖来源及验证范围。共享 HAL/CMSIS 版本与组合需核实，`latest` 标签不足以复现。无 Git 元数据时用源码快照 Hash 追溯。
