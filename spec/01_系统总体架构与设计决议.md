# 系统总体架构与设计决议（V1.9.1）

> **规范状态：** 当前有效架构规范。跨文件冲突按 `00_工程基线与唯一权威规范.md` 裁决；本文件只定义系统架构、模块职责和产品边界。
> **INS决议：** M3仍保持可插拔EstimatorPort；QUAD_X4首版选用KF-GINS_QUAD（21维核心+1维Baro bias扩展），详细算法和移植约束见05号文档。

源码分层、模型绑定和构建接入见 [03 §0](03_平台软件架构与驱动设计.md#0-flight-项目目录与现有工程接入)。

## 1. 系统总体架构与职责边界

### 1. 系统定位

本项目在现有 Flight BSP 工程上扩展多平台自主移动系统：唯一公共核心、稳定公共 Port/ICD、编译期 Product Profile、车辆专用实现，以及对现有 BSP 的受控适配。不同车辆共享契约和基础服务，不共享被强迫统一的 FMS 状态图、导航状态扩展、运动参考语义或控制算法。

### 2. 架构不变量

1. M1～M7 公共核心只有一份；按车辆选择实现，不复制整套业务目录。
2. 每个可插拔 Port 由唯一 Product Profile 绑定恰好一个兼容实现。
3. M3 只负责导航估计和观测级质量，不拥有任务、模式、返航/停车/靠泊决策。
4. M4 是所选车辆的唯一操作决策者，拥有权限仲裁和操作级故障响应。
5. M2 负责样本质量；M3 负责观测门控；Sensor Integrity Manager 负责源级隔离/恢复；M4 负责操作响应。
6. 真实运动异常、模型失配、执行器饱和不自动等同于传感器故障。
7. M6 输出物理语义 ActuatorDemand；M7 是唯一实物执行器输出入口。
8. RT-Thread 原生 Device Framework 是唯一驱动框架；不得自建并行 DeviceInstance/DriverManager。
9. 仅工程师需要反复辨识/整定的被控对象、传感器外参、导航噪声和控制增益集中在精简 `config/`；硬件/编译结构、安全策略和算法内部常量各归其主责位置。
10. PlantTruth 只用于 Host/SIL/HIL，不得反馈到实机估计器或控制器。

### 3. 七大业务模块

| 模块 | 主职责 | 唯一拥有/输出 | 明确不负责 |
|---|---|---|---|
| M1 通信与任务入口 | RC/GCS/Companion接入、协议解析、命令去重、来源标识和请求排队 | Transport状态、OperationRequest | 不决定飞行模式/Authority，不直接改任务状态 |
| M2 传感器管理 | 消费驱动样本、时间修正、校准、滤波、样本质量和源级诊断证据 | SensorSample/Quality/SourceHealthEvidence | 不拥有底层驱动、总线、DMA或导航估计 |
| M3 导航估计（INS插件） | KF-GINS惯导传播、异步观测融合、误差状态反馈、导航快照/能力/估计器健康 | NavigationSnapshot/NavigationCapability/EstimatorHealth | 不做任务决策、路径规划和电机控制；内部算法不向消费者泄漏 |
| M4 车辆管理（FMS） | 任务生命周期/任务项推进、模式、Authority、Home、Geofence、PreArm、LandDetector、Failsafe | MissionStatus、FmsStateSnapshot、VehicleDirective、AuthorizedMissionSnapshot、SafetyEnvelope、ActuationPermit | 不做路径搜索、MPC、姿态/角速度控制 |
| M5 制导与轨迹 | 消费M4授权的当前任务项，局部地图、路径搜索、轨迹生成/验证、手动参考适配 | MotionReference、PilotControlReference、GuidanceStatus、GuidanceFeasibility | 不拥有MissionStatus/任务项推进/Authority，不签Permit、不输出电机需求 |
| M6 控制 | MPC外环、SO(3)姿态设定、Rate PID角速度环、Control Allocation | ActuatorDemand | 不选择任务/模式，不直接访问电机驱动寄存器 |
| M7 执行器适配 | Permit/Demand/Epoch/TTL复核、物理限幅/slew、通道映射、DShot packet编码 | PreparedActuatorFrame/ActuatorStatus | 不做控制分配，不直接访问TIM/DMA寄存器，不替代PLANT |
| PLATFORM | RTOS、BSP、Device Framework、具体驱动、时间/存储/健康服务 | 硬件访问与平台服务API | 不做任务/导航/控制策略 |
| PLANT | 真实机体、ESC、电机、桨叶和物理动力学；Host/SIL/HIL仿真模型 | 物理响应/仿真真值 | 不是H723固件功能模块；PlantSimulationPort仅Host/SIL/HIL |

HEALTH & DIAGNOSTICS 是横向基础服务，不是第八个车辆业务模块。Sensor Integrity Manager 是其子服务，唯一拥有传感器源级健康/隔离/恢复状态。HEALTH 不重复运行模块本地检测，也不替代 M4 作操作决策。

### 4. 五类健康维度

| 维度 | Owner | 典型证据 | 不能推出的结论 |
|---|---|---|---|
| Device Health | Driver/BSP + M2 汇总 | 自检、总线错误、设备离线、复位 | 不能直接决定返航 |
| Sample Quality | M2 | CRC/序号/饱和/冻结/范围/采样时间 | 单样本坏不等于整台设备永久损坏 |
| Measurement Consistency | M3 | innovation/NIS、残差、跨源比较 | 残差大不必然是传感器故障 |
| Navigation Solution Health | M3 | 状态有效性、不确定度、可观能力 | 导航退化不由 M3 决定飞行模式 |
| Vehicle Dynamics / Control Health | M3/M6/M7 分别提供证据 | 突发加速度、跟踪误差、饱和、执行器响应 | 不应自动隔离传感器 |

健康状态必须分层保存；不要用单一 `healthy/degraded` 覆盖设备、样本、观测和车辆能力。

### 5. 关键数据流

```text
RC/GCS/Companion -> M1 -> LinkStatus + OperatorInput + OperationRequest
                                              |
                                              v
Sensors -> RT-Thread native drivers/DMA -> M2 -> M3 -> NavigationSnapshot/Capability
                                      |      |
                                      |      +-> EstimatorHealth / NavigationCapability -> HEALTH/M4
                                      +-> SensorDiagnostic
                                               |
                         Sensor Integrity Manager
                                | SensorUsePolicy -> M3
                                +-> FaultSummary -> M4

M1 OperationRequest/OperatorInput/LinkStatus --------------------> M4
M3 NavigationCapability + M5/M6/M7/energy/environment health ---> M4
M4 VehicleDirective + AuthorizedOperatorInput ------------------> M5
M5 MotionReference ----------------------------------------------> M6
M3 NavigationSnapshot + M4 SafetyEnvelope + M7 ActuatorStatus ---> M6
M6 ActuatorDemand -----------------------------------------------> M7
M4 ActuationPermit ----------------------------------------------> M7
M4 GroundStopCertificate (ground-only, after matching Permit revocation) -> M7
M7 ActuatorCommitReceipt ----------------------------------------> M6
M7 -> RT-Thread native Device Framework -> Physical Actuators
```

M1 报告链路事实，不判断飞行策略；M4 仲裁操作权限。M3 发布导航状态，不经 M4 中转。M6/M7 分别报告控制/执行器异常证据。M4 根据能力和阶段决策。

`GroundStopCertificate` 是 M4→M7 的窄范围、撤销 Permit 后地面停机事务，不是 M6 Demand，也不是通用 failsafe-to-zero。当前 FMS 适配器只在已确认 LANDED+DISARMED、匹配的 M4 DecisionEvent/撤销 Permit 和 Host/SIL `SIM_CONTROLLED_STOP` 策略下签发；H723 `BENCH_INHIBIT` 不开放物理输出。

### 6. 故障判断原则

- 直接设备/链路证据（自检失败、总线超时、数据冻结、CRC 连续错误）可以快速判为设备/数据链路故障。
- 单次创新超限只拒绝/降权该次观测并发布证据；不能直接永久隔离源。
- 持续观测不一致需要结合独立来源、共同时间源、杆臂、运动学和环境状态判断。
- 多个独立传感器一致显示真实运动，同时控制输出/执行器反馈出现对应响应时，优先保留外部扰动/模型失配假设。
- 仅凭 IMU/GNSS 残差不能识别“风”或“鸟”；应标记为 `UNEXPECTED_MOTION/IMPACT_SUSPECTED`，由多证据和产品策略决定响应。
- 源隔离、导航能力降级、车辆操作模式变化是三个不同动作，由不同 Owner 完成。

### 7. 通信与操作员权限原则

RC、GCS 数传、Companion 三类链路独立监控。链路恢复不等于操作权限恢复。RC 恢复后只有显式模式开关或已启用的接管手势才能夺回人工权限；摇杆中位不是自动接管信号。默认在 RTL 中恢复链路但无人明确接管时继续 RTL，不因“等待时间到期”自动切回手动。接管后默认锁存人工权限，摇杆回中不自动恢复 RTL。

### 8. 模型和参数边界

Estimator Model 归 M3 实现；Control Prediction Model 归 M6；Plant Simulation Model 仅 Host/SIL/HIL；Actuation Effectiveness 归 M6；Actuator Calibration Map 归 M7。可共享经确认的参数来源，但不能混用模型角色。质量、惯量、推力模型、杆臂/安装外参、导航噪声和控制器增益进入四份工程调参文件；FDIR/FMS/通信安全策略不进入日常调参集。`doc/calibration/` 保存原始证据，最终生效外参只在 `sensor_alignment.yaml` 保留一份。

### 9. 首版产品

首版仅 QUAD_X4：STM32H723、RT-Thread 5.3.0 原生 Device Framework、航空 FMS、KF-GINS_QUAD（21+1维）、Aerial Guidance、MPC + SO(3) + Rate PID、X4 执行器适配。UGV/USV 仅为接口草案，当前不接纳生产/Host兼容性PASS，不列入实物放行。

### 当前架构决议：GNSS独立运行

1. PLATFORM本地单调时钟是系统时间主时钟；UM982 GNSS/PPS是QUAD_X4主要器件的固定接入，外部信号失效不停止本地计时。RTC、Companion和其他同步源可按硬件另行配置。
2. GNSS不再是系统启动、IMU时间戳、INS传播、控制调度或日志排序的前提。
3. PA3/TIM2_CH4 IMU DRDY捕获始终工作；PA2/TIM2_CH3 PPS仅在GNSS Profile启用时工作。
4. `LOCAL_ONLY`表示无外部UTC参考但本地时钟有效；不得报成TIME_BASE_FAULT。
5. GNSS导航丢失与UTC/PPS丢失分开处理；M3评估导航能力，PLATFORM评估时间质量，M4决定车辆操作。
6. 运动中GNSS观测丢失后的能力边界、Home/局部返回和航空FMS场景由05号文档定义；这里不表示可以不安装或默认裁剪UM982。
7. 本地时间故障必须由PLATFORM发布TIME_BASE_FAULT；GNSS丢失不得触发本地时钟失效。

### 1.1 FMS / CONTROL / INS / PLANT概念映射

- **FMS = M4**：任务、模式、权限和飞行安全策略唯一所有者。
- **CONTROL = M6**：MPC、SO(3)、Rate PID和控制分配。
- **INS = M3插件**：导航估计器可插拔；QUAD_X4首版绑定KF-GINS_QUAD，其他产品可选择符合EstimatorPort的其他估计器。
- **PLANT = 真实物理机体/动力系统**；PlantSimulationPort仅用于Host/SIL/HIL。PLATFORM是飞控软件平台，不能与PLANT混称。
- **M7不是PLANT**：M7是执行器适配层，底层TIM/DMA波形由PLATFORM具体执行器驱动完成。

## 2. QUAD_X4 第一版产品边界（当前规范）

第一版实物目标仍为QUAD_X4。M1接入RC/GCS/Companion并报告通信事实；M2负责样本处理；M3负责INS/导航状态；M4唯一拥有五正交操作状态、权限和Failsafe；M5本机生成路径/轨迹；M6执行平动MPC、SO(3)、Rate PID和X4控制分配；M7复核Permit并输出DShot。HEALTH/Sensor Integrity是横向服务，不是第八个车辆业务模块。

第一版硬件配置清单输入：ADIS16505-2；RC/USART3/115200（Flight.xlsx与05已统一名称ELRS，实物型号/串口协议待核实）；数传USART2/MAVLink2/115200；DShot300/600协议候选；通用X型四旋翼SIM_ONLY模型；通用W25Q64 8MiB；SDMMC1 4-bit；Companion临时USART1并与Debug互斥。时钟/TIM/外设频率以Flight.xlsx记录为清单基准，并由真实`.ioc`/生成代码核验。

在线避障软件框架、SIMULATION和STATIC_MAP属于软件验证范围；真实飞行Profile固定`OBSTACLE_SOURCE_MODE=NONE`，直到真实传感器适配和安全验收完成。未证实的硬件Kill、ESC反馈、物理避障传感器不得在系统能力声明中出现。

V1.9.1的设计修订状态、目标编译、目标硬件和飞行放行是独立门禁；文档修订不构成实机放行。

当前可落地顺序为H723 BENCH_INHIBIT传感器/软件集成与Host/SIL软件闭环；GNSS/Baro/Mag辅助和实物运动只有提供08/12所列证据后才启用。协议未证实时显式DISABLED，不由上层猜测设备配置。该范围是编译期Profile约束，不能把规范修订完成解释为固件已实现或可以试飞。
