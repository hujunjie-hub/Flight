### 1. 两套优先级体系必须分开

RTOS 线程优先级和 NVIC 中断优先级是两个独立编号空间：

- RT-Thread：数值越小，线程优先级越高；0 最高。首版配置 32 级，31 留给 Idle。
- NVIC：数值越小，中断优先级越高；H723 的 NVIC 实现 4 个优先级位，逻辑优先级 0–15。
- 不得把“RTOS 优先级 4”和“NVIC 优先级 4”理解为同一等级。
- 同一优先级的线程会按 RT-Thread 时间片规则轮转；关键实时线程不共享优先级。

#### 1.1 RT-Thread 固定配置

```c
#define RT_THREAD_PRIORITY_MAX       32
#define RT_TICK_PER_SECOND           1000
#define RT_ALIGN_SIZE                8
#define RT_USING_OVERFLOW_CHECK      1
```

线程全部使用静态 TCB + 静态栈，通过 RT-Thread 原生静态线程初始化接口创建；高频/关键线程禁止使用动态堆分配线程栈。`rt_thread_create()` 只允许开发期或低优先级非关键服务使用。

若启用软件定时器线程：

```c
#define RT_USING_TIMER_SOFT          1
#define RT_TIMER_THREAD_PRIO         23
#define RT_TIMER_THREAD_STACK_SIZE   1024
```

软件定时器回调只允许置事件/投递轻量消息，不得运行滤波、MPC、协议解析或日志写入。若没有实际使用需求，关闭 `RT_USING_TIMER_SOFT`。

`FinSH/MSH` 仅开发/维护构建启用；量产飞行构建关闭。`Idle` 固定优先级 31，业务线程不得使用 31。

#### 2.2 快速链路执行顺序

```text
ADIS DRDY capture
  -> SPI1 RX/TX DMA
  -> DMA completion ISR + SPI EOT确认
  -> SensorIngestTask (P2)
  -> M2ImuProcessTask (P3)
  -> M3InsPredictTask (P4)
  -> NavigationSnapshot latest snapshot
  -> M6FastControlTask (P5, 最高1053Hz（标称1kHz）)
  -> ActuatorDemand双缓冲
  -> M7OutputCommitTask (P6, Demand事件 + 独立1kHz安全唤醒)
  -> TIM1/DMA硬件产生DShot300/600波形
```

- P2–P6保持严格优先级顺序；M6收到新鲜状态后执行SO(3)、Rate PID和allocation，不等待MPC。
- M6FastControl目标最高1053Hz（标称1kHz）；MPC独立50Hz，只通过完整快照提供外环加速度参考。MPC失败不得阻塞M6。
- M7OutputCommit由新Demand事件和独立1kHz安全唤醒共同驱动；即使没有新Demand也检查Permit/Demand TTL、M6 heartbeat、control_sequence单调推进、Timer/DMA状态和输出策略。它只做本地许可/范围/变化率检查和输出提交，不执行PID/MPC/控制分配。物理波形边沿由TIM/DMA硬件产生，不由RTOS任务抖动决定。
- DShot bit rate、1kHz控制和400Hz帧刷新是三种独立速率；TIM1运行时位时序、TIM2_CH1帧闹钟、bit0和zero-tail事件顺序唯一见板级§3.0.1。本节不再维护另一套旧计算或“机制未定义”结论。
- 跨任务快照采用03的双槽pin协议；高优先级读者不自旋等待低优先级写者，不读取正在复用的槽。复制完成即释放pin。
- 900µs目标定义为从IMU DRDY硬件捕获到M7完成Permit/关联校验并使新命令可供输出硬件提交；不包含DShot整帧物理发送完成时间。此为目标值，需DWT/GPIO/逻辑分析仪验证。

### 3. NVIC 中断优先级基线

#### 3.1 分组和优先级位

- STM32H723 Cortex-M7 NVIC 使用 4 个有效优先级位，逻辑优先级范围 0–15。
- 使用 `NVIC_PRIORITYGROUP_4`：4 位抢占优先级、0 位子优先级；本项目不使用子优先级。
- 所有 IRQ 优先级由 BSP 单一表配置，禁止驱动在运行期私自改优先级。
- CMSIS/HAL 设置的是逻辑值 0–15；不要手工再左移 4 位后传给 `HAL_NVIC_SetPriority()`。

#### 3.2 RT-Thread ISR API 约束：纠正 V1.8 的 syscall-threshold 表述

RT-Thread v5.3.0 Cortex-M7 端口的 `rt_hw_interrupt_disable()` 在该版本 `context_gcc.S` 中通过读取 PRIMASK 后执行 `CPSID I` 实现；这会屏蔽所有可配置的普通中断，而不是 FreeRTOS 风格的 BASEPRI syscall threshold。

因此：

1. **不得配置或引用 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 这类 FreeRTOS 参数。**
2. 本项目以本节作为代码约束：NVIC 0–3 完全禁止调用 RTOS API；NVIC 4–12 只允许调用已验证的 RT-Thread ISR-safe 通知 API。当前TIM2_IRQn=1，DMA1 Stream0/1=4，RC=5，GNSS=6。
3. 所有 ISR 遵循 RT-Thread Cortex-M BSP 的 `rt_interrupt_enter/rt_interrupt_leave` 规范；如果 BSP 向量封装已经调用，驱动不得重复调用。
4. ISR 禁止 mutex、阻塞 wait、动态内存、printf/FinSH、文件操作、滤波/矩阵计算和长循环。
5. `rt_hw_interrupt_disable()`/全局关中断临界区：目标最长 <2 µs，任何路径绝对不得超过 5 µs；必须用 DWT/逻辑分析仪验证。禁止在临界区复制整包数据或执行浮点计算。
6. NVIC 优先级不能绕过 PRIMASK 全局关中断窗口；真正不能被软件调度延迟的电机保护必须使用 TIM Break/外部硬件门控，而不是仅靠高优先级 ISR。

### 4. 传感器读取和总线仲裁优先级

传感器“读取优先级”不是单纯按 ODR 排序，而是按数据时效、飞行安全影响和总线是否共享来安排。

#### 4.1 采集优先级

| 级别 | 数据源 | 首版策略 | 处理优先级/时效 |
|---|---|---|---|
| S0 | IMU | 专用 SPI + DRDY + DMA；不与慢速传感器共享 SPI；1 kHz 每样本服务 | 最高；DRDY 到 INS 状态目标 ≤ 600 µs（含SPI DMA、M2处理及M3传播），sample age+uncertainty超过§7.2上限视为无效，不能只用DRDY后的处理时长 |
| S1 | RC 接收机 | 独立 UART DMA；解码任务P7；latest command snapshot | 高；帧 age > 30 ms 触发链路降级/失联策略（最终值按协议确认） |
| S2 | Rangefinder/Optical Flow | 独立数据源；降落/低高度/避障时提升处理关注度；总线事务有 deadline | 中高；正常 age 50 ms，具体按 ODR/模式设定 |
| S3 | GNSS | UART circular DMA；异步时间戳融合；不等待 INS | 中；允许延迟融合，样本超过历史窗口直接拒绝 |
| S4 | Barometer | 定时/DRDY；latest + bounded ring | 中低；age 100 ms 触发降级证据 |
| S5 | Magnetometer | 独立低频采集；磁干扰时可拒绝观测 | 中低；age 100 ms 触发降级证据 |
| S6 | GCS/Companion/ADS-B/Telemetry | DMA/协议队列；不占用 IMU 总线；过载丢低优先级数据 | 低于飞行闭环 |

RC 数据不是 INS 传感器，不进入 M2/M3；但其解码和权限状态必须及时提供给 M4/M6。

#### 4.2 总线拓扑硬约束

- IMU 使用独立 SPI 外设和 DMA 通道，优先级 S0。禁止把 IMU 放到与 Baro/Mag 共用的 I2C 低速总线上。
- RC 和 GNSS 优先使用独立 UART + DMA；不得用轮询读取阻塞控制任务。
- Range/Baro/Mag 若共用 I2C，总线仲裁采用固定优先级队列：Range/Flow（在降落/避障模式）> Baro > Mag > 诊断设备。
- I2C/SPI 单笔事务必须有最大执行时长；不得在持有总线锁时等待传感器转换或等待 RTOS event。转换等待期间释放总线。
- 任何低优先级事务不得连续占用共享总线超过 500 µs；无法满足时必须拆分事务或调整总线拓扑。
- GNSS、RC、GCS 等 UART DMA 独立运行，不参与 SPI/I2C 总线仲裁。

#### 4.3 慢速传感器的模式相关优先级

降落/低高度时，Rangefinder/Optical Flow 的数据处理 deadline 可以提升；这只改变 M2/M3 的事件处理预算或队列服务次序，不允许在飞行中动态修改 NVIC 优先级。模式切换由 M4 发布需求等级，M2 根据预先配置的固定策略执行。

### 5. 初始栈分配和栈安全

#### 5.1 栈大小表

第 2.1 节已给出每个线程的初始栈大小。生产构建按表静态分配；`FinSH` 额外 4096 B 仅开发构建。生产线程栈按本文件任务表合计52.5KiB（含Main/Init、CriticalFlash、Idle和可选Timer）；关闭Timer为51.5KiB。FinSH的4KiB开发栈放D3 SRAM4普通CPU专用区。另给MSP/ISR栈4096B。

#### 5.2 MSP/ISR 栈

- Cortex-M7 Handler/ISR 使用 MSP；RT-Thread 线程上下文使用各自线程栈（PSP）。
- MSP 初始分配 4096 B，放 DTCM，8-byte aligned。
- 设计上只允许有限嵌套：应用外设 IRQ 仅使用 1–12，SysTick/PendSV 15；ISR 禁止浮点运算、递归和大局部数组。
- 若实际嵌套深度超过 3 层、HardFault/BusFault 诊断路径需要更多栈，或 MSP watermark 使用超过 70%，必须扩到 6144 B 并重新核算 DTCM。
- HardFault handler 不得 printf；只保存最小 crash record（异常栈帧、CFSR/HFSR/BFAR/MMFAR、当前任务、时间戳）到保留区，再进入复位/安全停机流程。

#### 5.3 栈监测和放行门槛

- 所有线程栈启动时填充 pattern，运行时读取 high-water mark；静态分析启用 GCC `-fstack-usage` 或工具链等效功能。
- 正常压力测试下每个线程最大已用栈不得超过分配量的 70%；至少保留 30% headroom。
- 任一线程剩余栈 < 25%：验收失败，必须扩栈或减少栈使用；发生 overflow/canary 破坏立即阻止 Release。
- 对 MPC/KF-GINS_QUAD 等矩阵工作区，禁止把大数组放在线程栈；必须使用固定维数静态workspace，栈只放小型临时变量。
- FPU lazy stacking 和异常嵌套必须纳入最坏栈测试；ISR 不使用浮点，避免 FPU context 对 MSP 造成不可控压力。
- 开启 `RT_USING_OVERFLOW_CHECK`；若启用 MPU stack guard，必须验证 RT-Thread v5.3.0 对应 Cortex-M7 端口和 MPU 区域配置后再作为强制保护。

### 6. 缓冲区容量基线

#### 6.1 统一容量公式

对每个生产者/消费者队列：

`N_required >= ceil(f_max * T_block_max) + N_burst + N_margin`

再向上取 2 的幂，便于环形索引。UART DMA buffer：

`B_required >= (baud / 10) * T_service_gap * safety_factor`

8N1 按每字节约 10 bit 估算；首版 safety_factor 取 1.5–2。容量不能代替时效要求：队列即使还有空位，过期数据仍必须拒绝。

### 7. 数据新鲜度、队列策略和过载处理

#### 7.1 必须同时监控的指标

每个 ring/queue 统计：`current_depth`、`high_watermark`、`overflow_count`、`drop_count`、`oldest_sample_age_us`、`producer_sequence`、`consumer_sequence`。

#### 7.2 统一时间/容量门限

| 常量 | 设计值/含义 |
|---|---|
| IMU 驱动原始样本队列 | 4 槽，满时丢弃新记录并累计 `raw_dropped` |
| MAX_IMU_PIPELINE_DELAY_US | 3000us，具体滤波配置必须经标定证明不超此上限 |
| MAX_EVENT_TIME_UNCERTAINTY_US | 100us；无证据不得当作实测精度 |
| MAX_NAV_INPUT_AGE_US | 5000us；按evaluation_time-StateTime+uncertainty计算，超过拒绝 |
| DRDY_TO_M7_READY_BUDGET_US | 900us；不含400Hz等帧及DShot物理发送 |
| MAX_FEEDBACK_AGE_AT_FRAME_US | 7500us设计上限=5000us输入年龄+2500us最坏等帧；ESC响应另需T_act实测/安全验证 |
| DEMAND_TTL_US | 最多5000us，最终截止取Header/领域/Permit/参考许可中的最早者 |
| PERMIT_LEASE_US | 最多25000us；M4新评估可续租，旧数据不能续租 |
| DIRECTIVE_LEASE_US | 最多50000us |
| GUIDANCE_REFERENCE_LEASE_US | 最多40000us，未来480ms预览不等于消息新鲜度480ms |

`MAX_IMU_PIPELINE_DELAY_US`是唯一硬门限：包含传感器已辨识group delay、轴间对齐和M2处理预算；不另设第二个“对齐延迟”常量，也不得按旧1.8ms预算解释。

物理时间预算链：校准后pipeline≤3000us+DRDY后整链≤900us+事件不确定度≤100us=4000us，留1000us至5ms输入门限。帧刷新最坏另等2500us，所以反馈到帧上限7500us；ESC响应T_act仍须测量。超过pipeline/链路/不确定度任一上限拒绝相应目标Profile，禁止改写StateTime。

#### 7.3 队列满时的分类行为

- IMU：不允许 overwrite-oldest；记录缺失序号/时间范围，停止将不连续数据伪装成连续数据，M3 降低导航可信度，M4 决定降级。
- GNSS/Baro/Mag/Range/Flow：按时间戳和观测价值处理；过期观测丢弃并计数；不能阻塞 IMU。
- RC：摇杆数据采用 latest-value；模式/接管边沿事件使用独立 event ring，不能被摇杆刷新覆盖。
- GCS/Companion：命令队列和轨迹队列独立；过期/重放/错误 epoch 拒绝；低优先级数据可丢。
- Logger/Telemetry：允许丢弃非关键记录；绝不反压实时任务。

### 8. 延迟融合和慢速传感器的资源边界

M3活动状态由M3InsPredictTask(P4)唯一写入，P9在独立shadow计算；统一日志、fusion_revision、checkpoint generation、去重/全观测重放及提交条件见05 §5.3。P9每5ms最多400us，数值不可分单元≤60us，replay job最长60ms。接纳按源最小间隔和已验证WCET证明可追赶；超额/逾期/无历史拒绝辅助观测并降级能力，不挤占1kHz主传播。

入队age≤20ms与完成deadline是两个不同约束；物理历史跨度184ms与256ms delta容量是安全余量。不得沿用无条件“2×实时/20ms内追赶”的承诺。每次记录源ID、sample/arrival/开始/完成时间、日志水位、重传播步数、fusion_revision和拒绝原因。扩展VIO/Flow/Range、改变ODR或允许age时，必须同时更新CPU/RAM/接纳证明和测试。

### 9. 响应时间分析和 CPU 预算

#### 9.1 不能只看“CPU 使用率 70%”

每个固定优先级任务都要进行响应时间分析。首版使用：

`R_i = C_i + B_i + Σ ceil((R_i + J_j) / T_j) * C_j`

其中：

- `C_i`：任务 WCET；
- `B_i`：最长资源阻塞/临界区阻塞；
- `T_j`：更高优先级任务最小到达间隔；
- `J_j`：释放抖动；
- 还要单独加入 ISR 干扰和全局中断屏蔽时间。

必须满足 `R_i <= D_i`。如果不满足，不能简单调高该任务优先级；应先缩短 WCET、减少阻塞、调整采样率/任务结构或减少非关键负载，再重新计算。

#### 9.2 资源目标

- 常态平均 CPU 利用率目标 ≤60%；
- 规定最坏场景持续 CPU 利用率不得超过 85%（保留至少15%未分配CPU余量）；
- DRDY→M7新命令可用目标≤900µs，距950µs最短IMU周期保留50µs端到端时间余量；该余量需由目标测量证明；
- 所有硬实时任务 deadline miss 计数必须为 0；
- ISR 总 CPU 占用目标 <5%；
- 全局关中断临界区目标 <2 µs，绝对上限 5 µs；
- RAM 静态/动态峰值后仍保留至少 20% 可用余量；
- 关键线程栈至少 30% headroom。

#### 9.3 必测最坏组合

IMU 最大 ODR、GNSS/VIO 延迟观测同时到达、MPC 最大迭代、RC 高速帧、GCS/Companion 满负载、CAN 突发、日志队列高水位、DMA buffer 回收延迟、FDIR 事件风暴、故障注入和传感器恢复同时发生。

### 2.1 方案B冻结决议：PPS与IMU DRDY共用TIM2（本版沿用）

本版正式选择方案B：

| 信号 | MCU引脚 | GPIO复用 | 捕获通道 | 说明 |
|---|---|---|---|---|
| UM982 PPS | PA2 | AF1 | TIM2_CH3 / CCR3 | 主要GNSS器件的固定PPS硬件捕获；脉冲丢失时保持使能等待恢复 |
| ADIS16505-2 DRDY | PA3 | AF1 | TIM2_CH4 / CCR4 | IMU数据就绪硬件捕获 |

PA2和PA3均映射到TIM2对应输入通道；TIM2是32位通用定时器，CH3/CH4可独立输入捕获并共享同一个计数器。TIM2硬件输入捕获在边沿到达时锁存CNT到CCR，捕获值不受CPU进入ISR的延迟影响。

#### TIM2配置基线

- TIM2配置为32位向上自由运行计数器，`ARR=0xFFFFFFFF`，不在每个PPS边沿重置计数器。
- 目标计数频率建议约10 MHz（100 ns/tick）；最终`TIM2_TICK_HZ`必须根据实际RCC timer kernel clock和PSC计算，不得假定时钟树已固定。
- 10 MHz时32位计数器约429.5 s回绕一次；启用UIF更新中断并扩展为64位单调时间。捕获值扩展必须正确处理CC3/CC4与UIF同时挂起的边界情况。
- CH3/CH4按实际PPS和DRDY电气有效边沿配置；输入数字滤波保持最小必要值，避免引入不必要的边沿延迟。
- `TIM2_IRQn`是共享向量，统一优先级1；ISR禁止RTOS API。必须在一次ISR中处理所有已置位的CC3、CC4、UIF和CCxOF标志。
- CC4事件在ISR中通过预配置、无锁、非阻塞的驱动快速路径启动SPI1 RX/TX DMA。不得在该ISR调用阻塞HAL、mutex、动态内存、printf或普通线程接口。
- TIM2输入捕获本身不额外占用DMA Stream；SPI1仍使用DMA1 Stream0/1。
- PA4/EXTI4不再承载IMU DRDY，PA4释放为未分配引脚。开发板实施时将ADIS DRDY实际接至PA3；若当前开发板排针/跳线仍接PA4，需改线。仅修改软件无法完成物理迁移。

#### 64位时间戳扩展与异常

- 维护tim2_overflow_hi和time_epoch；UIF扩展高32位，外部mapping_epoch由TimeService独立管理，不与溢出混用。
- 若CC3/CC4捕获标志与UIF同时置位，依据CCR值和回绕边界规则判断捕获发生在溢出前还是溢出后，避免高32位错一。
- 检测`CC3OF/CC4OF`；发生overcapture时递增丢失计数并发布时间捕获故障，不允许将后续捕获伪装成连续数据。
- PPS和DRDY同一时刻附近到达时，两个CCR分别保留各自硬件锁存值；ISR必须处理两个标志，不依赖软件先后顺序推断边沿时刻。
- 由PLATFORM Time Service将扩展后的TIM2 tick转换为`FCU_MONOTONIC_US`；M3只消费标准时间戳，不直接访问TIM2寄存器。

### 2.2 必装GNSS与运行中信号丢失的板级行为

- 当前QUAD_X4固定GNSS_SUPPORT=1、GNSS_PPS_CAPTURE=1；每次启动均初始化UART4 RX circular DMA1_Stream2、PA2/TIM2_CH3捕获和健康/时间适配路径，不提供裁剪GNSS的生产配置。
- 无Fix、串口数据中断或PPS丢失不改变引脚/DMA/IRQ Owner，不关闭UART4或CH3；持续接收/捕获真实信号以支持恢复。
- PA3/TIM2_CH4、TIM2 UIF扩展、IMU DMA、本地monotonic在GNSS丢失时持续运行；GNSS质量不与TIME_BASE_FAULT混用。
- UART4初始化失败/主要器件缺失是必需设备故障；上电未获Fix是获取/未就绪状态，位置任务按导航门禁等待。M4决定已批准的运行降级响应。
- DMA1_Stream2始终归UART4 RX，不因暂时无数据而重新分配；PPS恢复需重新验证连续间隔/UTC配对，不重置TIM2/time_epoch。
- RTC/TCXO没有列入当前硬件输入，是否增加仍需BOM/原理图确认，不能用其可选性解释GNSS可裁剪。

#### 3.0.1 DShot当前实现基线（目标波形仍待验证）

两级预装序列依据[ST AN4776 Rev.5 §1.4.2及Figure 6](https://www.st.com.cn/resource/en/application_note/an4776-how-to-use-generalpurpose-timer-peripheral-on-stm32-mcus-stmicroelectronics.pdf)的preload→active机制推导：UEV锁存发生在该事件触发的DMA写入生效前。本节给出规范事件模型，尚非H723目标波形验证；实际寄存器行为以受控RM0468/HAL和量测为准。

- Flight.xlsx中的TIM1 kernel=275MHz、PSC=274、ARR=2499是启动/默认配置；DShot使能时，平台DShot驱动运行期覆盖TIM1 PSC/ARR，Flight.xlsx硬件清单不修改。
- 实际TIM1 kernel频率由受控RCC读回。PSC=0，N=round(F_TIM1/bitrate)，ARR=N-1，T0H=round(3N/8)，T1H=round(3N/4)，误差须≤1%。275MHz仅为示例：300k时N917/344/688；600k时N458/172/344。默认台架编译选DSHOT300，600需另行验波形。
- 400Hz是帧刷新率（2.5ms），不是DShot bit rate。Time Service使用TIM2_CH1内部比较闹钟调度帧启动；若TIM2标称tick为10MHz，标称比较间隔25000 tick；实际由TimeService当前连续映射把下个mono帧截止反算为raw compare，保留相位累加和整数余数；频率驯服后不能永远硬加25000而偏离mono时间。该通道无GPIO映射、无DMA。
- 每帧16bit packet，OC1PE..4PE固定开启。CEN=0/UDE=0、通道关闭时把CCR全零，UG使active全零；随后preload=bit0，CNT=ARR，清UIF。DMA缓冲为bit1..15+zero1+zero2，共17×4=68个uint32；DCR.DBA=CCR1/DBL=3，经DMAR依次写四个CCR。启用DMA/UDE、通道/MOE（此刻active仍零），最后CEN。第一次自然tick触发UEV，bit0才进入active，DMA写bit1；避免先使能输出导致bit0脉宽被软件延迟拉长。不得以软件UG直接启动非零active。
- TC时zero1已active、zero2已preload。UIF会合并，不能以“再等一次IRQ”证明完整零尾。CEN写入后读取TIM2 raw为保守启动上界t_start_hi；收尾门限为t_start_hi+ceil((1+18N)*F_TIM2/F_TIM1)+两个TIM2 tick guard。TC置pending；TIM1_UP ISR每次只检查绝对raw门限，到期才关通道/MOE/CEN并保持低。该门限覆盖启动tick、16数据位和两个完整零尾；延迟/合并IRQ只延长低电平。raw跨回绕使用05扩展值；计数运算全部整数且验证溢出，ISR无浮点/RTOS。TC/UP异常超过80us帧上限锁存driver故障，由已批准输出policy处置。
- 下一帧必须同时满足400Hz闹钟、IDLE_LOW、frame token未过期、boot/time/permit watermark匹配；ISR仅读已编码不可变数据。正在发送期间撤销不能把旧许可重新安装，至多完成已启动帧；下一帧立即失效。真实硬件紧急切断仍依赖已接入的Break/外部门控，不冒称软件可撤回已经发送的位。

- M7只准备DShot packet/输出缓冲并提交许可；PLATFORM DShot driver独占TIM1、DMA2 Stream2及TIM2_CH1回调。实际脉宽/边沿/帧间隔在上机后用逻辑分析仪调整，但不阻止当前软件架构与驱动实现。

#### 3.1 为什么这样分配

- IMU SPI1 RX/TX使用DMA1 Stream0/1，保证高优先级、短数据包、全双工Burst搬运。
- RC USART3 RX使用DMA1 Stream6，NVIC优先级高于GNSS和数传。
- GNSS UART4 RX使用DMA1 Stream2，循环DMA承接460800 baud数据流。
- USART2数传RX/TX分别使用DMA1 Stream5/7，避免阻塞发送和轮询接收。
- USART1的Debug与Companion临时角色共用DMA1 Stream3/4；单一Profile只能启用一种角色。Companion Profile为MAVLink2/115200并关闭Debug/FinSH；不得重复分配缓冲或DMA。
- I2C2电流计使用Flight.xlsx给出的DMA2 Stream0/1。
- DShot按Flight.xlsx记录占用DMA2 Stream2（TIM1_UP，四路CCR共享Burst）；Stream3–7保留。DMA1 Stream0–7均已分配。任何改变均须提交CR。
- DMA2_Stream2_IRQn当前配置优先级2，属于禁止调用RTOS API的高优先级中断；ISR仅清标志、记录DMA完成/错误和更新有界原子状态，不得调用RTOS API/日志/阻塞函数。M7通过独立1kHz守卫检查输出状态。

### 5. 传感器采集链路和时间戳

#### 5.1 ADIS16505-2 / SPI1

- SPI模式：Mode 3、MSB first、16-bit word（按数据手册）。
- Burst读SCLK按≤1.0 MHz保守设计；项目 `doc/Flight.xlsx`记录的954.861 kHz低于该值，仍必须在目标板实测实际SCLK。
- 16-bit burst包含11个16-bit时隙（22B，仅手册对照）；本Profile固定32-bit burst 17个16-bit时隙（34B），BURST32=1/BURST_SEL=0，不提供运行时格式切换。
- DMA槽固定64 B，固定BURST32传输34B。
- DR边沿到来时，TIM2_CH4硬件将计数器锁存到CCR4；TIM2_IRQHandler读取捕获值并启动SPI RX/TX DMA；DMA TC后必须确认SPI EOT，之后才能释放CS。时间戳来自CCR4，不使用ISR入口时刻替代。
- ADIS输出数据寄存器更新时间不等于物理运动测量中心时刻。数据手册默认滤波配置下gyro/accel group delay约1.29–1.57 ms；最终有效采样时刻必须按实际FILT_CTRL/DEC_RATE配置和台架测量补偿。
- 若偏离当前固定32-bit burst或更改内部滤波/decimation，必须同步更新slot长度、DMA时长、sample time模型和M3噪声/延迟参数。

#### 5.2 UM982 / UART4 + PPS

- UART4_RX使用DMA1 Stream2循环接收，2048 B初始buffer。
- UART4 IDLE、DMA HT/TC和错误中断协同维护producer index；parser按帧长度/CRC/序号消费。
- PPS经PA2 AF1/TIM2_CH3硬件输入捕获；IMU DRDY经PA3 AF1/TIM2_CH4硬件输入捕获；两路共用TIM2 32位自由运行计数器，分别读取CCR3/CCR4。
- GNSS位置/速度的sample epoch优先使用UM982消息内部时间；UART DMA完成时间仅是接收时间，不能代替测量时间。
- 460800 baud下2048 B约覆盖44 ms连续字节流；若消息集合造成更大突发，按实际最大输出字节数重新计算。

#### 5.3 BMM350 / BMP585

- BMM350：PB5/EXTI9_5通知M2，I2C1事件/错误中断完成数据读取；100 Hz。
- BMP585：PE1/EXTI1通知M2，I2C4事件/错误中断完成数据读取；100 Hz。
- 首版不分配DMA，避免为低频短事务增加DMA资源和Cache管理复杂度。
- INT极性、锁存/脉冲模式、清中断顺序必须按器件实际配置核验，不能仅依赖EXTI边沿。

### 7. 必须修正的原表述/风险点

#### 7.1 W25Q64 持久化设计

当前驱动通过 RT-Thread MTD 注册 `nor0`，`BENCH_INHIBIT` 固件启用关键事件环。A/B 参数事务、维护租约和只读导出仍属后续工作。以下地址为芯片内字节偏移，擦除单位 4 KiB，页编程上限 256 B。目标板仍需核验识别、几何和时序。[Winbond W25Q64JV 数据手册](https://lv.mouser.com/datasheet/2/949/w25q64jv_revj_03272018_plus-1489671.pdf)

| 分区 | 起始地址 | 结束地址（含） | 容量 | 内容/约束 |
|---|---:|---:|---:|---|
| Factory/Board Identity | 0x000000 | 0x00FFFF | 64 KiB | 出厂身份与校准摘要，运行期只读 |
| A/B Parameter Journal | 0x010000 | 0x02FFFF | 128 KiB | 各槽首个 4 KiB 扇区启用，分别从 `0x010000`、`0x020000` 开始。格式和提交见 08 §9.1、§12 |
| Recovery Metadata | 0x030000 | 0x03FFFF | 64 KiB | 预留，首版复位原因写入事件环 |
| Critical Event Ring | 0x040000 | 0x0FFFFF | 768 KiB | 解锁/锁定、模式和失效保护切换、关键故障与拒绝、启动和复位证据 |
| Emergency Blackbox | 0x100000 | 0x1FFFFF | 1 MiB | 预留，后续可用于故障触发的低频上下文 |
| Reserved | 0x200000 | 0x7FFFFF | 6 MiB | 保留 |

**任务与写入许可。** `applications/tasks/flash/task_flash.c` 负责调度。A/B 设置和事件环分别由 `middleware/storage/settings_journal/`、`middleware/storage/event_journal/` 管理，共用存储模块内部的 MTD 分区访问边界。物理驱动留在 `sensor_device/storage/W25Q64/`。读写接口检查分区、字节范围、对齐和完整传输，首版仅开放表中的 A/B 两个扇区和事件环写入，启动不自动格式化。

现有 `RuntimeEvent` 在入队前按事件类型筛选，使用独立的静态 RT-Thread 消息队列投递，首版 16 条，满时计数。故障持续期间只记录状态边沿，重复拒绝按来源和原因限频。启动时由板级代码在清除复位标志前保存原始值，`task_flash` 异步写入启动记录。监督超时事件携带稳定的任务编号。使用 `boot_id` 和 `event_id` 关联 SD/遥测，同一次启动的复位记录使用保留编号 0。未提交的 RAM 事件可能随掉电丢失。

`task_flash` 独占 NOR 会话，优先级低于 `task_supervisor`。启动扫描分段执行，设置尚未可用时使用编译默认值。控制、采样、监督和 SD 任务均不等待 NOR，NOR 故障通过独立状态统计待写、丢弃、I/O 错误和空闲扇区数。首版编程和擦除仅在输出受抑制的台架模式或 DISARMED 维护租约内执行。M4 在租约有效期间拒绝 Arm，直到器件结束忙状态。若超时后状态未知，保持维护互锁并进入存储故障处理。飞行中追加须经目标板验证后启用，只允许在已擦除扇区编程和回读，擦除和设置保存留在地面。工作栈、队列和扫描缓冲优先用 DTCM，当前固件增量目标为 DTCM ≤4 KiB、AXI ≤256 B，接入时核对链接图和栈水位。

**关键事件环。** 每扇区 4 KiB，包含 64 B 扇区头和 63 条固定 64 B 记录。192 个扇区共 12,096 个物理记录槽，实际留存扣除预擦除扇区和废弃槽。逐扇区轮转，地面维护目标为保留两个确认已擦空的扇区。已有新扇区完成提交后才回收最旧的有效扇区。无可用空间时保留已有记录并计数，交由地面诊断处理未知格式和无法识别的扇区。

| 记录 | Little-endian 字节偏移 |
|---|---|
| 扇区头 | 0–3 为 `FSEC`，4 为版本 u16，6 为分区编号 u16，8 为扇区代次 u64（从 1 递增），16–55 保持 0xFF |
| 事件 | 0–3 为 `FEVT`，4 为版本 u16，6 为事件类型 u8（1 启动，2 运行事件），7 为严重级别 u8，8 为 boot ID u64，16 为单调时间 u64（µs），24 为时间 epoch u32，28 为事件 ID u32，32 为来源 u16，34 为原因命名空间 u16，36 为原因 u32，40、44、48 分别为权限、指令和许可 epoch u32，52 为详情 u32（例如复位标志或超时任务编号） |
| 两者公共尾部 | 56 为 CRC32C u32，覆盖字节 0–55。60 为提交字 u32，值 `0x434F4D4D` |

按字节编码，版本与分区编号首版取 1。先写正文和 CRC，再回读校验，最后单独编程提交字并回读。恢复时按已提交且校验通过的扇区代次排序，只接纳格式和校验均通过的记录。扫描活动扇区的全部记录槽，从最后一个非全 0xFF 槽之后继续追加。半写槽跳过，擦除过的扇区经全扇区回读确认后才能重用。写入结果不确定时先回读判定，读取失败则停止使用该扇区。地面维护可经 `task_flash` 分批只读导出，按 `(boot_id, event_id)` 去重并和 SD 记录关联。

**实施顺序。** 先接通 MTD 分区和静态消息队列，再实现复位与关键事件落盘及 A/B 设置保存，最后按 09 验证掉电恢复和实时隔离。飞行中追加单独验收。

#### 7.2 SD卡基础布局

当前实现使用 RT-Thread DFS v1/Elm FatFs R0.16，挂载 SDMMC 的 `sd` 块设备，使用已经格式化的 FAT32 卡。`task_logger` 每次启动或存储故障恢复时分配新的 `/LOG/Fxxxxxxx/` 目录。`STATE.CSV` 记录名义 20 Hz 状态快照，`EVENTS.CSV` 记录独立的 16 槽 RT-Thread FIFO 中的事件。快照使用非阻塞互斥读取，事件投递有界，存储拥塞只丢日志。文件每秒刷新，并按 64 MiB 会话上限滚动。SD 读写错误后关闭文件并限频重试，首次识卡与热插拔由 SDMMC 驱动能力决定。

日志记录 FCU 单调时间、IMU 样本与质量、导航时间和有效位、NED 位置速度、姿态、模式与失效状态、控制需求和提交回执。物理量用列名标明单位，状态和事件使用同一 boot ID。记录路径和字段见应用说明。

使用单一 FatFs、512 B 扇区和 ASCII 8.3 名称。日志任务挂载现有文件系统，创建会话目录并独占文件。SD 卡型号、持续吞吐、写入时延及掉电恢复按目标实测验收。

#### 7.3 实时与存储隔离

控制、估计与中断路径使用既有 IPC 和设备接口。SD 文件操作全部在 `task_logger` 中执行，卡缺失、写满和超时只影响日志。事件队列独立于遥测，满时统计丢弃。W25Q64 分区和独立关键事件持久化约束见 §7.1。

### 10. 第二轮容量补账

完整枚举对象后的ICD参考占用41376B超过原40KiB，故ICD_AND_M4_ARENA统一48KiB，不能忽略新增类型。M1单独8KiB：去重32×96B、长操作4×128B、两个channel RX 2×280B、P0 TX4×280B、低级TX4×280B、来源会话4×64B、scratch512B，共7152B；ACK完整Header按缓存的轻量结果重建，不在cache额外复制112B对象。M1 staging任务放ICD指定槽，不重复预算。

### 固件资源审查与优化顺序

以同一 GNU Arm release 配置的 `Flight.bin`、`Flight.map` 和 ELF 段为基线。先去除可证明的重复状态，再做受控构建优化，最后以完整固件和回归结果比较。

1. M3 将配置中的上三角协方差直接写入已分配的核心矩阵。初值正定性验证借用影子核心数值工作区。周期检查点直接写入环的下一槽，写入成功后才推进环位置。保留 active/shadow、原精度、历史窗口和 journal 容量。
2. 规划任务在自己的控制快照内生成制导结果，独立导航能力只在其消费者处保留。任务通过互斥发布和复制快照，算法调用保持在临界区外。
3. M5 将深度优先验证的待处理栈与总访问预算分开。预览栈上界为 24 个根区间加 5 层细分，围栏全段栈上界为 8。仍执行 256 次总访问预算、原最大深度和连续约束。
4. GNU Arm release 对初始化、存储、诊断及协议支持组选用体积优化。导航、制导、控制、执行器及应用控制任务保留原优化级别。把 `.data` 的装载段归入 Flash 区域，让链接器同时核算 Flash 副本与 RAM 运行段。比较 Flash 装载字节、AXI RAM 静态占用与独立 D2 DMA 占用。
